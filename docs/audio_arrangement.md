# 多轨音频编排

2026-09-09，R5 媒体增量。音频片段是作品配乐数据，视频片段仍是可组合的图节点；
二者使用同一作品时间。没有新增播放器、设备服务或第二条 FFmpeg 解码链。

## 创作与播放

- 在音频面板选择音乐后，作品音乐区的“添加为音频片段”将其导入不可变资产库，
  追加到编排末尾。已有单曲配乐会先转换为第一条片段。普通“绑定”仍表示替换配乐。
- 时间线显示各音频片段：拖动摆放、拖动两端调整播放区间，可按 BPM 吸附。
  源入出点独立编辑；移动摆放不改源裁剪。可以复制到播放位置、移除、静音，
  编辑音量、左右平衡、淡入淡出和源区间循环。一次连续拖动产生一次撤销。
- 提交片段编辑后重建音频游标；同一作品保留播放位置和暂停状态。拖动过程先显示
  草稿，松开后应用混音，避免每一像素都重开解码器。清除、撤销、重开和发布保留编排。
- 所有有效片段混合为一条双声道 48 kHz PCM 流，进入现有有界输出队列及音频分析器。
  音乐驱动节点得到混音特征，画面时间跟随设备消费的音频；没有每轨独立时钟。
- 导出窗口音乐文件留空时采用作品编排，填写文件时显式替换配乐。
  预览和离线导出共享 `AudioMixer`、源裁剪、包络、左右平衡及混合规则。

## 明确范围

| 项目 | 当前合同 |
| --- | --- |
| 片段预算 | 最多 32 条，任一采样时刻最多 4 条重叠；静音片段也计入预算 |
| 时间 | 非负，摆放结束及源入出点不超过 7 天；对齐最近的 48 kHz 采样 |
| 速度 | 原速；没有变速、变调或保调拉伸。视频仍遵守自己的速度合同 |
| 源结束 | 静音或在裁剪区间内循环；不保持末采样，避免直流输出 |
| 混音 | 各轨增益 0–1，立体声平衡 -1–1；双精度求和后统一限幅，再转 float PCM |
| 淡入淡出 | 共用 `EnvelopeGain`，线性或平滑；重叠的淡入淡出按比例缩入区间 |
| 资产 | 编排配乐与普通素材共用 32 MiB，内存包最多 48 MiB；同源压缩数据共享；P5 字体预算变更见 `text_rendering.md` |
| 单首大音乐 | 原 `music-performance-v2` 的 256 MiB 文件范围模式保留；不用于多轨包 |
| 整体循环 | Player 可循环作品配乐；离线导出只走一遍编排，结束后补静音。片段内循环仍执行 |
| 波形 | 原有单文件波形保留；逐片段显示共享缓存的源包络，映射源裁剪和循环；不是最终混音波形 |
| 视频声音 | 不自动把视频内音轨加入混音；音频片段显式使用音频资产 |

当前 seek 沿用 FFmpeg 解码器的精确重放路径，源入出点在导入和发布准备阶段探测。
没有把此规格宣称为任意数量轨道、超大素材库、DAW 或保调音频工作站。

## 模块与兼容

`media_arrangement` 只验证不可变片段及采样计划；`media_mixer` 在媒体工作线程上
按需持有活动解码器。`audio_playback` 的内部 `AudioStream` 选择单曲或编排游标，
复用原设备输出、队列、分析和消费时钟。文件路径只存在于宿主到工作线程的适配值中。

工程 manifest 3 表示含音频片段，旧 manifest 1/2 继续读取。
发布 profile `music-arrangement-v1` 明确携带片段；不伪装成旧单曲 profile。
图程序 ABI 仍由图能力决定（没有 Cue 时 2，有 Cue 时 3）。修改 profile 以降级读取会被拒绝。
独立渲染核心没有网络依赖，通信仍后置。

参考 TiXL 的本地时间线音频代码；具体版本、文件摘要和不导入 BASS 服务的原因记录于
`provenance/audio_arrangement.json`。复用本项目的 FFmpeg、音频队列和时间片段代码，
不改变任何第三方许可证或项目尚未确定的对外许可证。

## 内置作品与验收

“光幕协奏 / Luminous Concerto”有 85 个节点、109 条边、两段原创视频、两份原创
合成音频源、四条音频片段、三段 Cue 和三个公开宏。总素材 834,058 字节，时长 16 秒。
源工程、源素材、生成脚本和真实 GPU 缩略图均随项目保存；Android 在内置目录直接选择。
这是编排示例，视觉品质仍待审核，不作为 R6 的基础/高级 50+50 质量目标完成证据。
