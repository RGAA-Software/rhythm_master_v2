# 光幕协奏：节拍演出示例

从 Studio 的“选择模板”或 Android 内置目录选择“光幕协奏”。保留可编辑的 94 节点、
八组音频响应光环、两段视频、四个音乐片段、三个公开宏和三个 Cue。

工程带有 120 BPM、4/4、原点 0 秒的节拍网格。依据是项目自己的
`tools/author-luminous-concerto.py::media_sources`：底鼓每 0.5 秒触发，低音同周期，
旋律以 0.25 秒细分；16 秒循环和 4/12 秒 Cue 都落在小节起点。不是从不可靠的
自动 BPM 数字推断相位。现有素材不重新编码，资产哈希保持原样。

1. Studio 中打开时间线并播放配乐；属性中的“节拍与量化”可查看或修改网格。
2. 把执行时机选为“下一拍”或“下一小节”，选 Opening、Chorus 或 Release，点击召回。
   请求显示待执行目标；暂停期间等待，恢复后在首个跨过目标的显示帧应用。
3. 等待期间可取消；反复召回同一目标不重复执行，选择不同目标后召回替换该类请求。
   修改网格、重启或跳转会取消旧请求，避免在错误的时间触发。
4. Chorus 加大响应、转速和辉光。现场召回只改变演出覆盖值；点击“跟随 Cue”恢复
   秒制编排。需要保存新的演出设计时捕获快照、编辑 Cue，再保存工程。
5. 保存、重新打开后网格保留；发布运行包同时保存网格、快照与 Cue。
   Windows/Android Player 从作品读取网格，执行时机默认立即，现场可选量化。
6. Player 中将另一内置作品加入演出队列，点击“下一场”，沿用同一执行时机。
   新场接管后使用新作品自身网格。当前跨作品配乐是切换，连续音频淡化属于 P3。

事件支路由节拍与音频瞬态分别触发包络，混合调制最终曝光；Cue 事件驱动步进，
改变饱和度。可以展开修改这九个节点并观察事件柱状图和包络曲线。
尚未录制的现场点击不会自动写入导出或工程；动作记录与重放属于 P2.4。
本示例仍标为品质审核待定，节拍合同通过不等于达到最终高级作品品质目标。
