## 1. 产品目标

Rhythm Master 的产品目标是对标 **TiXL 和 TouchDesigner 的实时节点式视觉创作软件**，
以音乐可视化为核心应用方向。对标贯穿自由创作、节点交互、实时反馈、参数控制、
复杂动态效果、组件复用和作品输出，而不只用于选择界面主题或示例效果。

用户能够从基础节点搭建原创作品，也能够展开、修改和复用已有组件与模板。纹理、
图像/视频、信号、粒子、几何体、场景和材质在明确的数据契约下组合。音乐文件或实时
音频的频段、响度、节拍等特征是核心驱动来源；时间、参数及其他已支持输入也能独立
驱动视觉，不强制每张图都连接音频节点。节点预览与最终输出持续反映编辑结果，
作品通过窗口、全屏、媒体导出或运行包交付。

- Studio：Windows/macOS 上的节点创作、参数编辑、音频与时间轴控制、性能分析、
  资源与模板管理、导出和发布。
- Player：Windows/macOS/Android/iOS 上的音乐可视化作品播放、音频输入、播放控制、
  画质设置与平台生命周期管理。
- 共享核心：音频特征、时间语义、图编译与运行、效果、渲染和工程/运行包契约。

Studio 的创作能力是产品主体；Player 承担作品的独立运行与跨平台展示。
模板是入门、学习和复用的入口，模板数量不能替代底层节点能力与自由编辑验收。
内容库只保留高端、可编辑的 Advanced 作品；目标是至少 50 个独立验收的 Advanced
模板。基础示例不再作为产品目录或数量目标。

### 对标能力与验收方式

以下是目标能力，不表示已经实现或达到上游软件的完整功能覆盖：

| 能力 | 本项目的完成口径 |
| --- | --- |
| 自由节点创作 | 能从空图构建原创效果；节点按数据域和用途分类；连接、参数与错误诊断清晰 |
| 实时可观察性 | 节点内预览、最终预览和参数修改形成实时反馈；大图交互与求值有可测预算 |
| 动态控制 | 常量、信号绑定、表达式、关键帧和时间轴可组合；音频驱动与动画具有统一时间语义 |
| 复杂视觉组合 | 图像/视频、合成与后处理、粒子、物理和 3D 能组合成完整作品 |
| 组件化与复用 | 子图/语义组件可封装、暴露参数、复用和继续编辑；模板保留创作结构 |
| 实时运行与交付 | 窗口/全屏、工程恢复、发布运行包与音画导出具备稳定流程和性能证据 |

按这些能力逐项记录现状、缺口和验收结果。已授权的音乐可视化主线继续推进，
不因对标软件存在某项功能就自动引入全部硬件协议、通用应用脚本或任意 UI 构建能力；
这些扩展仍需单独确定范围。

## 2. 范围边界

桌面壁纸、动态桌面背景、WorkerW/Progman 桌面嵌入、设置系统壁纸、壁纸会话和
壁纸专用启动模式均不在产品范围内，也不作为“最后再做”的待办。
旧仓库路径中的 `shark_dynamics_wallpaper` 仅用于历史来源和构建证据，不能据此
继承其产品定位。旧仓库和 GammaRay 原仓库继续保持只读，复用范围需独立审核。

窗口和全屏输出是音乐可视化展示表面。透明纹理、遮罩、图层合成等视觉能力继续保留；
透明原生窗口/后缓冲与点击穿透仍遵循此前“整体最后、待定”的决定，不能推导出
壁纸需求，也不阻塞当前产品验收。

## 3. 完成口径

1. **音频到画面**：真实音乐文件和支持的实时输入经同一音频分析契约驱动效果；
   验证不同频段、响度变化和静音状态下的视觉响应。合成输入测试不能代替真实音乐验收。
2. **编辑与时间**：从基础节点搭建原创作品、展开修改模板与封装复用组件均可用；
   节点连接、参数、节点预览和最终输出一致；音乐与动画的播放、暂停、
   跳转和循环使用明确的同步语义。各项未完成能力继续记录为待办。
3. **作品交付**：工程保存与恢复、资源管理、运行包发布与播放形成闭环；媒体导出明确
   音画同步、格式、取消和错误恢复要求。窗口与全屏展示不依赖桌面嵌入。
4. **复杂效果与性能**：模板同时验收视觉品质、音乐响应和可编辑性；测量帧耗时、
   音画延迟、GPU/内存预算及长时间稳定性。节点数量、模板数量或低 GPU 占用不能单独
   代表完成。内容目标是至少 50 个独立验收的 Advanced 模板；基础示例不再计入目录。
5. **跨平台播放**：共享契约从现在覆盖全部目标平台；分别记录编译、原生探针和实际
   APK/应用验收，不能将其中一项替代另一项。Android 需验证真实音乐、权限、设备中断、
   前后台恢复、画质和持续运行。

当前继续优先推进复杂场景性能、音乐与动画同步、Windows 创作/播放完整流程及 Android
Player。Apple 平台仍最后移植；通信开发和测试仍后置至整体最后阶段。
