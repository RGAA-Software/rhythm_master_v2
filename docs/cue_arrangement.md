# 快照 Cue 编排

R5 增量：在作品的统一时间上安排公开宏快照。每条 Cue 有稳定 ID、名称、开始
秒数、目标快照、过渡时长和平滑选项。最多 256 条，开始时间严格递增；范围
0–1e9 秒，名称最多 128 UTF-8 字节。错误引用、重复时间、非有限值及超限均拒绝。

## 创作与播放

时间线的“快照 Cue 编排”选择快照后，可在播放头添加 Cue、拖动位置、吸附到
当前 BPM 的节拍、修改名称/开始/过渡/目标，或删除。拖动预览释放后只有一个
撤销事务。BPM 吸附是编辑辅助，文件保存秒数；不暗中重定时已有 Cue。

第一条 Cue 前使用作者默认值；零过渡立即切换。线性或 smoothstep 过渡从 Cue
开始时的实际值向目标插值。若前一条淡入未结束，新 Cue 从当时的中间值接续。
采样仅依赖秒数，因此跳转、反向定位、循环后的重新求值与离线导出一致，不依赖
是否先播放了前面的 Cue。此确定性只适用于宏编排；GPU 粒子、反馈等仍遵守各自
既有的状态/预热和 seek 限制。

Studio 与 Player 显示当前宏值。手动滑块仅覆盖被改的宏，其余继续自动编排；
召回快照和手动 A/B 混合覆盖全部宏。“回到自动编排”清除覆盖并回到当前时刻的
值。Studio 同时把宏编辑写入作者默认值并保留原有撤销事务；捕获快照取当前
自动/手动合成的值。修改默认值不会重写以前的快照。保存不把临时覆盖状态带入
Player。Android 对话框展示当前 Cue 名称，每 200 ms 刷新数值；UI 不拥有播放钟。

`ControlSequence::Crossed(from,to)` 提供有界的前向事件 ID 查询，区间为 `(from,to]`，
反向或等时刻不重复发事件；零秒 Cue 可由 Active(0) 查询。该 API 与值采样分离。
当前交付的是快照编排和本地事件查询，尚未提供任意动作脚本、网络事件、外部
触发协议或通用图内事件调度器，不能据此宣称完整演出控制系统。

## 版本与边界

有 Cue 的编辑工程使用 GraphProject schema 5，运行程序使用 ABI 3；旧播放器
必须拒绝新 ABI，不允许忽略 Cue 后继续播放。无 Cue 的工程和运行包继续写原有
schema/ABI，当前读取器仍支持旧格式。已有图片/音乐运行包 profile 保持各自资产
与音乐语义，program_abi 决定程序能力；manifest 与 protobuf ABI 必须匹配。

Cue 在主图生效，组件沿用输入端口接受宏值。编译保留作品 Cue，裁剪不参与输出
的宏快照条目；若最终输出没有任何公开宏，运行包不携带空编排。删除最后一个宏
或删除目标快照会清理相应 Cue。元数据未知字段仍按 ID 保存，wire 预检查限制
256 条 Cue 与 128 字节名称，避免解析前无界分配。

本增量复用参数快照、Studio 历史、图编译和已有播放时钟/FFmpeg 输入/离线导出。
参考 TiXL 的播放时间与片段映射契约，见 `provenance/cue_arrangement.json`。
不引入第二个播放器、媒体时钟或网络通信依赖。

## 内置作品与验证

| Cue | 开始 | 目标 | 过渡 |
|---|---:|---|---:|
| Opening | 0 s | Quiet | 0 s |
| Rise | 2 s | Concert | 2 s |
| Climax | 8 s | Peak | 2 s |
| Release | 12 s | Quiet | 3 s |

与 16 秒演示音乐循环配合，首尾均回到 Quiet。同一作品的扩展不增加模板计数。

已显示随音乐推进的 Cue 名称与插值控件值。日志 `out/r5-cue-delivery-tests.log`、
