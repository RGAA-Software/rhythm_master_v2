# 模型动画与姿态

2026-09-08，R4 持续开发。已实现 GLB 节点 TRS 动画、关键帧采样、两段动画混合、
统一时间、节点预览与共享静态上传；48 骨骼蒙皮已通过两端 GPU 与运行包检查。
morph 顶点渲染继续开发；当前权重采样契约通过测试，不表示 morph 已能显示。
R4–R6 尚未全部完成。

## 创作流程

导入含动画的 GLB，连接 `geometry.glb → geometry.animate → scene.instance`。
主动画和混合动画可按名称选择；资产尚未准备好或经组件转接时显示片段编号。
混合比例可以连接音乐信号。未接时间输入时使用作品统一时间；显式时间输入支持
局部时间、曲线和其他信号。速度范围 -16..16，偏移 ±86400 秒，支持循环或端点保持。
两段动画使用同一秒数，各自按片段长度循环；不是归一化相位同步。

更换片段与参数沿用属性事务、撤销/重做、保存和运行包属性。现阶段导入动画资源
通过原 GLB 随包保存，两端均从同一资源读取，不另建媒体或动画时钟。

## 契约和预算

- `AnimationClip` 构造时验证，发布后只提供只读轨道；每次采样对时间二分定位。
- 支持 STEP、LINEAR、CUBICSPLINE。旋转线性使用最短弧 slerp；三次使用分量
  Hermite，按相邻时间差缩放切线，然后归一化。三次旋转不做符号半球修正。
- 时间必须非负、严格递增、有限，最长 24 小时；单帧片段有效。循环支持负时间。
  缺失通道保持模型默认 TRS；不同片段混合时也以同一默认姿态补齐。
- 每模型最多 64 片段、8192 通道、262144 个四分量值（含三次切线），姿态最多
  2048 节点。图最多 32 个动画求值节点，场景姿态层级缓存最多 65536 节点。
- 当前 glTF 通道只开放平移、旋转、缩放；矩阵节点不接受动画通道，稀疏访问器和
  压缩动画不在当前范围。零长度四元数、非有限结果、接近零的缩放拒绝。
- `Geometry` 共享不可变 `Model` 和基础上传 ID，另持有小型不可变姿态。
  动画/原始实例共用网格和内嵌图像上传；每实例层级姿态分别生成绘制矩阵。
  时间不变时保持快照，显式时间输入不会被自动时钟反复失效。

## 复用与验证

### 骨架增量

每模型最多 64 个 skin，每个 skin 1..48 个关节，保留 glTF 关节顺序。四影响权重支持
`JOINTS_0`（无符号 byte/short）和 `WEIGHTS_0`（float 或归一化 byte/short），导入时
检查有限非负值并归一化；零总权重、越界关节、缺失配对属性拒绝。没有提供逆绑定
矩阵时采用单位矩阵。关节可以经过普通父节点，不丢弃这些中间变换。

绘制调色板为 `inverse(mesh_world) * joint_world * inverse_bind`，外部实例变换单独
应用。每个已发布姿态只计算一次层级和调色板；原始网格和关节权重上传一次，
不同实例的姿态不会改写模型。切线生成分裂顶点时同步复制关节属性。

额外关节流为 20 字节/顶点，计入 128 MiB 网格预算。普通网格继续使用原 48 字节
布局。每个 ScenePass 最多缓存 65536 个骨骼矩阵（含默认/动画姿态），每个绘制列表
最多提交 65536 个矩阵。相同网格、材质、变形和骨骼调色板可以实例化。

GPU 先蒙皮，再执行已有扭转/收缩。位置与切线使用混合矩阵，法线使用混合基底的
逆转置并归一化，保留切线手性。线性蒙皮在关节旋转相抵时仍可能塌缩；近奇异基底
保留输入法线，未声称双四元数蒙皮或自动修复。阴影复用同一骨骼绘制记录。

Windows D3D11、手机 Adreno 650 GLES：48 骨骼、四影响、平移/旋转/非均匀缩放、
法线贴图，普通与实例化各四组比较，所有平均像素误差均为 0。D3D 的整数属性与
浮点 Shader 输入不匹配已修正为私有 UNORM8 传递/解码，两端高位关节 46/47 均参与
测试。运行包 GLB → 动画 → GPU 测试在两端得到相同 4.75676 像素位移，反复跳转
画面逐字节一致，始终只有一个网格上传。`scene_skinning`、`skin_render_contracts`
和扩展的模型导入测试通过。

本增量为共享核心和两端原生验证；完整新作品与 Studio/Android APK 交付会在 morph
接入后一并完成，没有把原生测试当作完整产品交付。

Hermite 后归一化规则，数值测试特意检查了有非零切线的差异。
