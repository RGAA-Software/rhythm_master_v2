# R5 场景准备队列与转场

本文保留 R5 首次交付的历史边界。后续持久列表见 [P3 列表](performance_lists.md)，
已连接两端的音画淡化、当前预算限制及实机证据见 [P3 配乐切场](audio_scene_crossfade.md)。
以下“配乐硬切／列表未持久化”只描述 R5 当时版本，不代表当前 P3 实现。

2026-09-09，首个功能增量已实现，Windows/Android 短功能验证通过。接续多轨媒体增量 `203a243`。

实现范围和证据见 [场景转场验证](validation/scene_transitions_2026-09-09.md)。
队列目前属于本次演出，不持久化播放列表；Android 的直接选择仍保存到原来的已选作品。

## 实施顺序

1. 复用 `PackageLoader` 和 `PreparedPackage` 建立宿主线程控制的有界 FIFO：
   最多 16 个条目，仅准备队首一场，显示等待、准备中、就绪、失败；
   删除/取消后的迟到结果不能覆盖下一条。失败留在队首供重试或跳过。
2. 独立转场合成器复用现有 `DrawList`、预乘透明合成和 `AspectFit`。
   先做切换及可调时长溶解，不新增专用图形后端或引入上游引擎。
   用已知 RGBA 图验证端点、中点、透明边缘和横竖画布。
3. 演出控制器组合两个 `Session`，后台准备不接触渲染资源。
   下一场在宿主帧边界获得 GPU 资源；两场共用既有 256 MiB 纹理预算和
   240 个离屏 pass 上限，不各自放宽。失败时保留当前场，不显示半准备的输出。
   转场期间不开始第三场的资源准备。
4. 转场进度从当前作品时间增量派生，暂停不推进；seek/循环造成的不连续显式处理。
   两场视觉和音频分析共享一个输入快照，不增加音频设备或竞争时钟。
   含独立配乐的作品在接管时切换配乐并定位到新场景已经展示的时间；
   无配乐场景保留正在播放的音乐。本增量不把音频硬切换宣传为跨作品音频淡化。
5. Windows Player 和 Android 增加队列、准备状态、开始转场、跳过/清除与时长控件；
   Android 继续从内置效果目录选择，不要求目录选择器。画布方向在成功接管时更新，
   转场中按当前画布等比适配下一场。保留原来的直接选择与普通播放入口。
6. 交付可直接演示的场景组合，完成短功能检查后更新两端完整部署与覆盖安装，
   记录范围和剩余缺口，再推进 R6 内容、浏览、资产修复、帮助和预览调度。

## 检查重点

- 队列满、无效包、准备失败、重试、删除准备中的条目、迟到结果、移动后的空包。
- 切换/溶解端点与中点，透明度、颜色和宽高比，暂停/恢复/定位/循环。
- 同时两个真实复杂场景的 GPU 资源峰值；超预算能返回当前画面，结束后旧资源释放。
- 不能只做空渲染器测试：Windows D3D11 和 USB Android GLES 都检查像素及界面操作。
- 当前音乐不中断的场景切换、带配乐作品的接管位置、循环和后台恢复分别验收。
- 长稳、热稳定和最终视觉品质仍最后集中验收。

## 已实现的产品入口与语义

Windows Player 点击“演出场景队列”打开可调整大小的独立窗口，选择内置作品并入队。
窗口只在第一次打开时设置初始尺寸，不按每帧内容自动缩小，也不挤占主播放器画面。
Android 点击“演出队列 → 添加内置作品”，复用带缩略图的内置目录。
两端均提供等待/预备/就绪/失败、移除、清空、重试、0–5 秒转场及取消。
0 秒为硬切；非零为显示空间 SDR 溶解，不是线性 HDR 光照混合或任意过渡 shader。

`SceneDeck` 持有唯一演出时钟，两场 `Session` 使用派生的场景局部时间。
暂停保留混合比例；主动定位、重新播放或音乐循环造成的不连续取消尚未完成的转场。
公开宏 ID 属于各自作品，下一场使用自己的默认值和 Cue，不套用上一场的手动覆盖。
成功接管后旧 GPU 所有者保留到当前帧提交结束，下一帧释放。
新作品配乐在接管时定位到转场期间已展示的场景时间；这是配乐硬切，不是双配乐交叉淡化。
无配乐作品保留现有音乐，音乐进度条仍显示真实音乐时间，场景状态另显示局部时间。

Android 临时导入复用抽取的 `ImportFile` RAII：只认本应用缓存中的 `incoming-*` 普通文件；
所有排队副本合计最多 512 MiB，最多 16 场，取消加载后等待工作线程退出才删除源副本。
仅预备或接管队列条目均不覆盖最后一次直接选择的持久包。
当前实现只有 CPU/媒体资产预备；下一场首次 GPU 创建仍在帧边界发生，不能据此承诺零卡顿。
