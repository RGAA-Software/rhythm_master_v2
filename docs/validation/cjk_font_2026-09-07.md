# Complete CJK font experiment, 2026-09-07 (superseded)

The user restored Microsoft YaHei. The following records the temporary experiment,
not the current UI font or a fix for the reported template-name corruption.
The actual cause was GBK-decoded authored metadata; glyph coverage and valid UTF-8
did not detect it. See `template_title_encoding_2026-09-07.md`.

The previous Windows host read `C:/Windows/Fonts/msyh.ttc` and otherwise loaded
ImGui's default Latin font. Its ChineseFull range did not include extension-A or
supplementary Han, and ImGui used 16-bit codepoints. These were coverage and
packaging weaknesses; an exact reproduction of every user-reported garbled label
was not available. Existing locale/template JSON passed strict UTF-8 decoding.

The host now loads the full unmodified Noto Sans CJK SC Regular 2.004 OTF from
`fonts/NotoSansCJKsc-Regular.otf` beside the executable. It fails explicitly on a
missing packaged font rather than silently presenting Latin-only glyphs. ImGui
and all consuming targets use `IMGUI_USE_WCHAR32`. Persistent ranges request all
Unicode characters; FreeType packs every encoded glyph available in this font.
The font is not subsetted to current UI text or the common Chinese block.

Source revision: `f8d157532fbfaeda587e826d4cd5b21a49186f7c` from
https://github.com/notofonts/noto-cjk . Font size: 16,437,364 bytes; SHA-256:
`2c76254f6fc379fddfce0a7e84fb5385bb135d3e399294f6eeb6680d0365b74b`.
OFL 1.1, exact upstream license and embedded copyright (2014–2021 Adobe) are retained
in notices. `provenance/noto_cjk.json` records the source and unmodified asset.
Existing vcpkg FreeType is reused; no vcpkg Noto font-asset port was found.

## Checks

- Font module built incrementally with 20 workers. `ui_font_contracts` decoded
  locale and template JSON strings, checked 644 distinct codepoints, including
  U+3400, U+9F98 and U+2000B, through `FindGlyphNoFallback`. No missing glyphs or
  UTF-8 replacement characters were found. Runtime atlas: 44,811 glyphs,
  4096×1867 pixels (30,588,928 RGBA bytes). See `out/font-glyph-test.log`.
- A real D3D11 capture shows new effect names, simplified/traditional text,
  extension/supplementary Han, Chinese punctuation and mixed Latin text:
  `out/windows/font-review/chinese-font.png` (raw TGA retained beside it).
- `out/font-integration-build.log` records Studio, Player and interaction-test
  rebuilds after the ImGui ABI change. The initial font test needed a non-const
  reference for this pinned ImGui's glyph lookup API; corrected before passing.
- All nine additional checks passed: source-boundary, host lifecycle/device recreation, deployment,
  Studio/Player smoke and four editor interaction suites are recorded in
  `out/font-integration-tests.log`. Main application bundles contain the complete
  font, OFL/provenance notices and all 16 runtime DLLs. The deployment smoke uses
  a system-only PATH and unrelated working directory.

Python resource synchronization stages the font for direct executable/test runs;
Python deployment copies it next to both original and deploy executables on every
application build, including resource-only deploy targets. The final bundles are:

- `out/windows/src/windows_spike/deploy/rhythm_master.exe`
- `out/windows/src/windows_player/deploy/rhythm_player.exe`

The prismatic-lotus project also opened with seven of seven inline previews and
rendered 30 smoke frames using the new font (`out/font-lotus-smoke.log`).

No system font, old project or GammaRay source was modified. This does not claim
coverage of every Unicode symbol or finish shaping, bidi, IME or DPI work. Android
uses its native host and was not changed by this Windows UI font correction.
