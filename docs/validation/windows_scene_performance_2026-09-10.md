# Windows 光门编辑性能定位与修订

## 范围与真实原因

基线为 d5136ce 的生产代码，新增短时测量入口。用户要求本轮只处理 Windows，
不构建、安装或验证 Android。原先 41.57／50.42 ms 来自导出期间的父窗口，
不能当成正常播放基准，也不能当 GPU 耗时。

复用现有 Host、Studio、Player Session、FFmpeg FilePlayback 和 bgfx 私有诊断。
相同 1280×720 窗口、当前 703 指令作品及其内置真实编排；每组预热 120 帧，
采集 480 帧，没有并行导出。每种模式的音乐位置按实际播放时钟推进，因帧率
不同采样时间窗不同；统计是交互负载对照，不是逐帧同时间像素比较。

单独 Player 的主线程工作约 1.6 ms，中位帧约 16.6 ms；Studio 全图视图主线程
约 29–32 ms，即使关闭预览仍很慢。全图缩放下活动预览为零，不能把预览开关
开着误认成每个节点都在重复渲染。现有场景实例合批约 99 次绘制，没有证据说明
它是本次低帧率主因，因此没有重排场景、改材质或降画质。

分段定位发现 UI 数据翻译约 12–14 ms，应用／画布约 13–14 ms。
UI 顶点／索引数组逐项追加且没有预留容量，在大图每帧产生多轮扩容与复制；
缩小到文字不可读、端口不到一像素时，仍然生成完整文字与圆圈几何。

## 实施

1. 在 Windows ImGui 适配器按上游 TotalVtxCount／TotalIdxCount 和命令数量
   一次预留容量，保留原有索引偏移、纹理解析、裁剪和提交顺序。
2. 在项目节点绘制适配器按实际屏幕字号决定细节：低于 6 像素不生成标签和端口
   圆圈，仍保留相同布局占位、端口命中、链接和节点拖动；放大后恢复细节。
   正常节点预览仍按既有可见性／预算规则工作，不关闭可读尺寸的图像预览。
3. 新增 tools/probe-scene-performance.py 和 scene_performance_probe 诊断目标。
   输出完整逐帧 CSV、音频 RMS、纹理／draw/pass、分段耗时与实际截图；
   通过 verify_windows.py 串行运行。不是长稳，也不自行宣布 FPS 验收合格。

bgfx 的 gpu_ms 在这条带垂直同步的路径中紧随呈现间隔；它保留为原始后端数据，
不把整个间隔解释为有效 GPU 工作。present_ms 同样包含等待；CPU、GPU 与帧周期
不能相互替代。未测其他电脑／分辨率／最坏图规模。

## 检查与失败保留

- 新诊断目标第一次漏链 project_io，编译拒绝；补齐目标依赖后通过。
- 初版探针用单音源 Load 读取编排，得到 audio.playback_source；改为既有
  LoadSoundtrack，与正式路径一致。没有静音空跑冒充真实音乐。
- 增加后端计时列时 CSV 表头遗漏，解析失败；修正表头后重测。
- 初版细节适配误解上游 GetCurrentZoom：查本地源发现它返回 InvScale。
  初版实测无改善，保留 out/scene-perf-lod.log；修正除法后再记录改善。
  该轮新局部名遮蔽旧变量的警告也被 /WX 拦截，修复后重新构建。
- Windows Host 合同、节点拖动／连线／右键平移、200/500/1000 节点双语言
  导航四项通过：out/scene-perf-interactions.log。实际放大图像预览与最终输出
  已查看；不以该短测替代全部 P8 或 P9。

## 正常字号视图的后续定位

继续滚轮放大到正常编辑尺寸时，暴露画布外节点仍生成端口／标签的浪费：
每帧约 27.8 万 UI 顶点／121.6 万索引，中位 19.89 ms、p95 26.79 ms。
因此增加画布裁剪范围检查；使用 BeginNode 覆盖为节点裁剪之前的画布范围，
以当前节点原点与布局尺寸判断细节可见性，布局与端口注册仍照常执行。
同一正常字号视图变为约 4.5 万顶点／17.8 万索引，中位 16.63 ms、p95 16.85 ms。
数据分别为 7e99862a26824e5c98aa17b85771f8df 和 692a921add8c4396971386a71bd050de。

额外右键平移后实际活动预览为 1，中位 16.58 ms、
p95 16.84 ms；最大长帧 69.34 ms 保留，不宣称消除全部尖峰。
数据：out/scene-performance/0d89065cb6e24c1e87a2616bf2b68c9c/。
较深缩放会触发异步预览计划重新编译，原 120 帧预热曾在编译中正确拒绝测量；
深缩放模式改为 240 帧预热，之后全部 480 帧都要求当前计划有效，未放松断言。
三种原始基准仍为 120 帧预热，没有把失败样本混入成功统计。

裁剪修改后的拖动／连线／右键平移、双语言大图导航三项再次通过：
out/scene-perf-clip-interactions.log。第一次完整 Windows deploy 九项通过，
out/scene-perf-delivery.log；裁剪修订后的最终 deploy 结果另记。

- 缩小／放大／定位与活动预览的功能证据已齐，本次解决大图的持续 UI 开销；

  完整逐帧指标，且要求测量期间存在真实音乐特征、定位／深缩放存在活动预览。
