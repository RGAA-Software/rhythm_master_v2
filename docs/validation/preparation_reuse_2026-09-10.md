# 局部文字编辑与资源准备复用

## 问题与实现边界

此前持久字体 glyph 缓存只减少字形栅格化；改变一个文字布局仍重新读取、
校验并准备全部引用资产，重复解析 GLB、解码静态图片和视频首帧、解码 Shader
容器，还会重新合成其他不变文字的蒙版。

现在 Loader 的唯一工作线程拥有 `PreparationCache`。GLB 准备模块拥有独立的
`model_assets::Cache`，只保留最近一次成功的模型目录；综合缓存只保留最近一次
成功的准备结果。每次仍验证当前记录、源字节哈希、MIME 和预算，缓存不能将
缺失、篡改或伪造类型的源变成成功。模型 MIME 原来未针对 GLB 检查，本次补齐。

模型和视频数据／首帧采用既有不可变共享值；图片、文字蒙版和 Shader 容器采用
既有值类型复制，避免重新解析／解码／栅格化，但不宣称零复制。字体 SHA 与完整
布局键匹配才复用文字蒙版。删除的资产不进入新目录，缓存没有无限增长的历史。
取消或整体失败不替换综合成功结果；模型子缓存可能已准备本次通过验证的模型，
仍是有界、不可变且经过当前源校验的目录，不会发布半套资源。

已有每份图像／模型图像合计 64 MiB、模型顶点／索引、视频实例、源字节和 Shader
预算继续执行。新旧两份准备结果并存会增加峰值内存；图像值复制部分至多两份
各 64 MiB，调用方仍可持有旧结果。字体缓存另有既有两字体／glyph 预算。
这不是全进程硬内存上限，也没有去掉磁盘读取和 SHA 成本。后台结果仍以单次
不可变快照发布，未把解码或字体排版移入 UI／渲染线程。

## 当前验证

- `out/p5-model-cache-tests.log`、`out/p5-model-cache-media-type-tests.log`：模型
  热加载共享同一模型，坏哈希／缺源／错 MIME 拒绝，失败不丢掉成功缓存，删除
  后重新加载确实重新解析。
- `out/p5-preparation-cache-tests.log`：模型、文字与源码边界检查通过。相同文字
  不再生成布局，重排已有字符只生成布局、不重复栅格化字形；字号、字体淘汰、
  损坏源、错类型和取消仍遵守合同。
- `out/p5-mixed-cache-build.log` 保留新混合测试首次构建失败：测试包含私有字体
  缓存头但未声明 `text_layout` 编译依赖；补齐测试私有依赖，不扩大产品公共依赖。

`out/p5-mixed-cache-test-dependency-build.log` 修正后构建通过。
`out/p5-mixed-cache-tests.log` 的模型、文字、混合场景及真实视频 fixture 四项通过。
混合图同时包含两个不同文字、GLB 场景、透明 PNG 和视频；只改一个文字后另一
文字不生成布局，模型／视频首帧保持共享身份、PNG 字节相同，旧结果不可变。
逐个损坏资产、改错 MIME、取消都拒绝；清空图再加载不保留删除的准备结果。

`out/p5-preparation-cache-android-build.log` 和
`out/p5-preparation-cache-android-tests.log` 记录当前 NDK 构建的模型、文字和混合
测试在 USB Android 上通过。这里是 CPU 原生合同，不是 Android 应用画面验收。
最终 Windows/Android 应用交付回归随系统输入法专项继续。
