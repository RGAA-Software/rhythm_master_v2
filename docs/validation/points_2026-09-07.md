# Initial point and particle pipeline

The portable `particles` module adapts focused first-party simulation algorithms
from the old repository; exact files, revision and hashes are in
`provenance/particles.json`. The original repository is unchanged. No third-party
particle textures or physics/lighting adapters were copied into this module.

Implemented: seeded rectangle/ellipse/ring emission, burst on a scalar rising
edge, lifetime variation, gravity, velocity, rotation, color/fade envelopes and
bounded fixed-step updates. Simulation runs at 120 Hz with at most 16 catch-up
steps per call. Excess real-time delay is dropped; this is not arbitrary-time
state replay. Seed changes reset the stream; reducing capacity bounds it
immediately. Snapshots are immutable values shared by graph consumers.

Four primitive operators form a typed Point pipeline: grid, emitter, transform
and renderer. Point outputs have colored ports and inline graphical previews;
the renderer produces a texture for the existing filter/compositing path.
Transforms preserve screen-space rotation across aspect ratios. Soft circles
use an owned procedural sprite; custom texture inputs and additive/source-over
blending are supported. Simulation is CPU based, with batched GPU drawing.
GPU simulation, fields, collisions, trails and indirect/instanced rendering
remain subsequent work; this increment does not complete step 4.

The initial profile limits one point output/emitter to 16,384 points and the sum
of source/intermediate capacities in a compiled plan to 131,072. Compilation,
package validation and runtime check the same budget before allocating point
state. Runtime implementation storage is now private so simulation/backend
changes do not expose their concrete types through the runtime API.

Studio disables arbitrary seek/loop for particle simulation, retaining pause and
restart until deterministic state replay exists. A Particle Fountain component
and Rotating Light Lattice template bring content to 54 presets / 15 templates.
The 40 semantic-node / 120-preset / 24-template milestone is still incomplete.

Windows evidence: `out/points-full-windows.log` exercised 53 suites; its one
failure identified missing default presets and the old catalog-count assertion.
After correction, `out/point-content-tests.log` passes content, templates, points
and deployed-app smoke tests. `out/points-device-android.log` passes both new
portable suites plus real Adreno 650 GLES pixels, including composed alpha and
square/soft-circle coverage through grid/transform/render.

Both Windows-published templates complete 30 Windows GPU frames and 60 Android
GPU frames (`out/particle_fountain-player-*.log`, `out/point_lattice-player-*.log`).
Device evidence: `/data/local/tmp/rhythm-master-points-20260907`. Native APK code
was rebuilt; APK installation/lifecycle/audio acceptance remains pending.
