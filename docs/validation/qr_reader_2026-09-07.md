# Android 扫码识别基础验证

当前是 `probes/qr_reader` 独立验证，未将识别库接入 Studio/Player，也未完成相机权限
或 App 扫码验收。Android 安装仍等待用户解除设备上的 USB 安装限制，不绕过它。

候选为 [ZXing-C++ v2.3.0](https://github.com/zxing-cpp/zxing-cpp/releases/tag/v2.3.0)，
提交 `d6068bcebeb8fd9f0d35a99b00d202be86a14dbe`，与先前 Python 独立图像验证使用的
版本保持一致；不声称它是最新版本。`prepare-zxing-probe.py` 固定源码、记录完整文件
哈希，拒绝未审阅的本地修改。只构建 reader，不启用 libzint writer、Qt、上游应用或
自动下载测试依赖。项目已有 Nayuki 编码器继续负责生成。

源码 Apache-2.0，内嵌 libzueci 1.0.1 标注 BSD-3-Clause，UTF-8 片段另有 Hoehrmann
许可说明。`third_party/notices/zxing` 保留根许可证、每文件版权、BSD 条款和片段原始
许可；未将所有内嵌代码笼统当作 Apache，也未选择项目出口许可证。

`src/qr_reader` 只向外暴露 luminance span、尺寸、行步长和不透明识别结果。ZXing 类型
和短借用地址仅在同步私有适配中存在；未知 QR 内容不会自动打开 URL 或执行动作。
最大 1,048,576 个逻辑像素、边长 2048、步长 4096、缓冲 4 MiB、结果 1024 字节。
原生相机适配必须先处理 Android Y 平面的 pixel stride/最后一行缺省 padding。

AsyncReader 复用有界基础 executor：一个 worker、一个 future，最多每秒接收五帧。
忙时拒绝当前帧；只复制逻辑 Y 行（最多 1 MiB），相机可立刻释放原始图像。
generation 严格递增；取消/新会话抑制旧结果，包括已经完成但尚未消费的结果。
当前 ZXing 同步调用不能中途抢占，销毁等待这一个受限解码任务结束，不以 detach 隐藏工作。

Windows/USB Android 已执行：原图、反色、低对比度、90° 旋转、行 padding 五种
合成图像；空白、缺字节、尺寸/步长/像素超限、1025 字节结果拒绝；输入复制、busy、
5 Hz 限流、时间回退、generation 切换、十次取消以及待处理任务销毁。
主图 455×455。首轮五种图像与边界检查约 Windows 5.6 ms、Android 14.8 ms；
后来加入更多边界与异步生命周期用例后整组约 Windows 13 ms、Android 42 ms。
这些是单次测试组墙钟时间，不能当成单帧延迟、相机帧率或现场鲁棒性承诺。

构建：`python tools/build-qr-reader-probe.py windows|android`，Windows 在已初始化的
MSVC 环境运行。执行：`python tools/test-qr-reader-probe.py --serial e2b3b128`。
证据、真实二进制哈希和设备目录在 `out/qr-reader/validation.json`。
每次 Windows 构建由 Python 更新完整 `out/qr-reader/windows/deploy` 与 SHA 清单。
