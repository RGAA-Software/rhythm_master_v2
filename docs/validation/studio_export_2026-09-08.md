# Studio 音画导出验收（2026-09-08）

Studio 工具栏的“导出音画”已接通作品快照、真实音乐、离线图求值、GPU 读回、
FFmpeg 编码和最终 MP4 发布。默认使用 H.264/AAC；可显式选择 MPEG-4/AAC。
这是 Windows 桌面导出的首个可用规格，不代表媒体编排和整项产品规划完成。

## 操作与规格

在 Studio 应用作品/组件修改，选择音乐，再打开“导出音画”。可设置目标 MP4、
音乐路径、时长、帧率、尺寸比例、码率和音量。默认采用当前画布、所选音乐及其时长。
音乐路径为空时输出无音轨视频。任务完成后显示并可复制文件路径；关闭面板不取消任务。

当前从作品起点导出，时长至多一小时，24/25/30/60 fps，偶数尺寸，单边至多 4096、
总像素至多 1920×1080，码率 4/8/16 Mbps。实际时长按整帧取整并显示。
音轨为 48 kHz 双声道，音乐结束补静音；输出增益不改变驱动视觉的源音乐特征。
已有目标文件不会被覆盖。错误或取消不产生最终文件，发布提交阶段不再接受取消。

尚未提供区间预滚、多轨混音、音乐编排、透明视频、全规格编解码器选择或 GPU 编码互操作。
组件工作台尚未应用的草稿不属于已应用作品；随后已接入
[作品音乐持久化](work_soundtrack_2026-09-08.md)，导出仍使用面板中明确选择的音乐/时长。

## 执行与边界

- `ExportJobs` 在有界后台执行器准备不可变作品和音乐副本，通过已有 SDL 进程 API
  启动同一部署程序的隐藏 `--export-job` 入口。Studio 的实时渲染不等待离线编码。
- 子进程拥有独立 host、渲染设备和 Runtime。音画仍复用项目媒体、图、视频与渲染接口。
  JSON 文件传递有界请求、进度和结果；没有增加网络通信服务或依赖。
- 实际集成发现 SDL 窗口线程的 STA 与 FFmpeg Media Foundation 编码要求冲突。
  `EncodingQueue` 在专属线程创建、使用和销毁 `AvWriter`，不改变 SDL 的线程公寓，
  也不把失败静默改成另一编码器。
- 最多三张 GPU 读回、两张排队编码图和一张正在编码图；有界背压只作用于离线工作。
  取消回调先注销、编码线程先退出，再销毁共享状态；GPU 挂起内存沿用既有设备生命周期。
- 私有临时目录建于目标文件同级，音乐分块复制并检查大小/修改时间。取消/失败会回收子进程
  和本任务目录。SDL 后台进程返回不能单独证明成功，必须具有成功收据和完整帧数。
- `storage::PublishNew` 原子发布新文件且拒绝覆盖：Windows 使用无替换标志的移动，
  Linux/Android 使用 `renameat2(RENAME_NOREPLACE)`，其他 POSIX 候选使用同文件系统
  硬链接。UI、graph 和 runtime API 不暴露 SDL/FFmpeg 类型。

复用来源见 `provenance/export_process.json` 与 `provenance/media_encoding.json`。
没有新增 FFmpeg 构建；继续使用已验证的 vcpkg LGPL SDK。

## 验证证据

`out/export-delivery-tests.log`：13/13 通过，包含源码边界、原子发布、媒体编码、
视频解码/纹理、异步读回、离线导出、后台作业、真实 Studio 导出操作与部署启动。

真实 ImGui/Studio/D3D11 回归打开 Resonance Live（197 个可达指令），选择 16 秒 PCM，
点击工具栏和开始按钮，通过部署 exe 生成 H.264 MP4，1280×720、30 fps、480 帧。
导出期间父编辑器仍执行 226 帧，主机帧耗时 p50 16.57 ms / p95 16.95 ms。
路径为 `out/windows-release/export-ui/465858214725800/Exports/音画验收.mp4`，
同目录上一级有 `export-ui.tga`。该 UI 回归将输出增益设为零以静默运行；不能用它证明可听音轨。

独立作业测试使用非零增益真实音乐，验证 H.264、Unicode 路径、并发开始拒绝、
已有文件字节保持、进行中取消、编码错误无发布和临时目录清理。
离线 GPU 测试对真实音乐做两次输出，逐帧解码相同且超过 50 个不同帧；静音改变图像。
4 秒 MP4 的解码 PCM 长度准确，音乐均方误差为 7.63e-6。
基础编码测试还覆盖 24/25/60 fps、AAC 整块和不足一块的尾帧。

Release Studio、Player 和各自 20 个运行 DLL 由现有 Python 构建/部署流程更新。
Android API 26 目标的更新后 `export_core` 编译通过；真机原子发布测试发现硬链接被拒绝，
改用内核禁止覆盖的原子重命名后通过成功/已有文件保留回归（`out/publication-android-tests.log`）。
采用内核调用避免引入 API 30 才导出的 bionic `renameat2` 符号；不支持时返回错误。
契约依据 [Linux rename 文档](https://man7.org/linux/man-pages/man2/rename.2.html)，
未复制上游实现。Android 原生编码与读回已有独立证据；本次不声称 Android 应用具备桌面导出 UI，
也不声称完成 Android 应用音频、生命周期和长时间验收。Apple 验证仍在最后平台阶段。
