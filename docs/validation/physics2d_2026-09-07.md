# Initial 2D physics validation

Box2D 3.1.1 from the existing `C:/source/vcpkg` port is the selected initial
Windows/Android 2D backend, with the project overlay port revision 1. Preparation:
`python tools/prepare-physics.py`. SDKs are isolated in `out/vcpkg-physics`;
the shared installed packages and old repository remain unchanged.

The unmodified library reproduced a sensor false exit on both platforms. A
circle of radius 0.2 overlapping a box edge at x=-0.5001 produced separation
0.000100017: `b2ShapeDistance` skipped radius subtraction below 0.1 linear slop.
The project patch subtracts radii for every requested rounded distance, retaining
the upstream witness-point adjustment threshold. No event debounce is used.
Direct API regression also checks separated shapes. Evidence:
`out/physics-native-unpatched.log`, `out/physics-patched-windows.log`,
`out/physics-patched-android.log`. Android used device `e2b3b128`.

The private RAII adapter verifies gravity, contact/hit/sensor values, stable
cross-world handle rejection, destruction, capacity/time validation, distance
constraints and motor hinges. Native worlds, bodies and joints are privately
owned values. The public API is host-thread confined and uses meters/radians.
Advance runs at 120 Hz with four solver substeps, at most 16 catch-up steps and
4096 copied contact records. Events for already destroyed bodies are omitted.
This bounds adapter work; it is not a worst-case performance guarantee for dense
native collision scenes.

`point.physics2d` integrates grid/emitter point streams with circle/box bodies,
restitution/friction/density, scalar gravity controls and optional floor/canvas
walls. It owns body movement after birth; incoming source positions/velocities
seed new bodies, source disappearance destroys them, and source generation
changes retire bodies even if point IDs repeat. Source appearance, age and color
continue to come from the emitter. Size changes recreate that body's shape.
Material/boundary settings reset the world; gravity controls preserve it.

Canvas height corresponds to 10 meters. Point positions and velocities use
normalized width/height; size uses canvas height and rotation radians. Gravity
controls use canvas heights per second squared. Valid authored canvas aspect
ratios are supported. At most 512 input points per physics node and 2048 across
the execution plan are accepted before native allocation. The four boundary
bodies per world are separate. Pause and restart are supported; timeline seek
and loop remain disabled for stateful emitters, physics and feedback.

`point_physics` tests typed compilation, floor radius on wide canvases,
immutable snapshots, pause/reset, normalized birth velocity, retirement and
source generation changes. Windows evidence: `out/physics-integrated-tests.log`
and subsequent targeted runs. Source lineage propagates through transforms and
physics. Point transforms rotate velocity with the canvas aspect ratio.

Full Windows build/deploy: `out/physics-full-windows.log`, 55/55 suites passed.
Android: `out/physics-full-android-build.log`; seven affected native suites pass
in `out/physics-device-android.log`, including actual GLES floor-contact pixels
and device recreation. Both new Windows-published templates complete 30 Windows
GPU frames and 60 Android GPU frames; logs use
`out/physics_{rain,pile}-player-{windows,android}.log`. APK archive verification
passes; this is separate from installation/device acceptance.

Two experimental templates, **Bouncing light rain** and **Falling block pile**,
expose curated controls through embedded components. The catalog now contains
58 presets and 17 templates. These counts do not complete the 120/24 targets.
Graph-facing contact event streams, custom collider input, joint authoring,
fields/trails, GPU simulation, 3D, performance/stability acceptance and APK
installation acceptance remain pending. Adapter joint validation is not a claim
that joint nodes are available in Studio.
