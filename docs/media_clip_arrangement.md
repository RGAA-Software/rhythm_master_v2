# 视频源区间与时间线

R5 视频片段增量。`texture.video_clip` 将既有 FFmpeg 视频源接入作品的统一时间，
公开摆放起点/时长、源入点/出点、0.125–8 倍正向速度、透明/保持/循环及淡入淡出。
`texture.video` 保留原有行为。新类型由旧版本明确拒绝，未改变旧节点含义。

## 创作与运行

在节点面板的纹理分类添加“视频片段”，在属性中选择已导入视频，连接到
`texture.stack` 或合成节点。图的连接顺序决定叠放顺序，时间线每行对应一个节点。
拖动条块移动摆放区间，边缘调整摆放时长；下方编辑源区间、速度和包络。
源入点/出点不会因移动摆放位置而改变。拖动沿用预览事务，松手只提交一次撤销记录。

- 时间单位为秒；`ClipInterval` 是纯时间映射，使用现有作品/音乐时钟，没有第二个播放时钟。
- 摆放与源区间均为左闭右开。区间外透明；透明结束模式提前在选中源播放完时停止。
  保持模式取源出点之前的最后一帧，循环模式只重复选中的源区间。
- 淡入淡出重叠时按比例缩短，线性或 smoothstep 与 `time.envelope` 共用同一实现。
  视频像素和顶点颜色为 straight alpha，内部合成遵循现有预乘透明契约。
- 解码帧未变化时，包络仍会更新输出；透明度变化不会重新解码或分配另一份上传纹理。
- 实时播放异步请求，离线导出等待精确需求；两者共用 FFmpeg 解码、PTS 选择与代次。
  出点明确排除，不被已有 PTS 浮点比较容差越过。
- 源出点超过已知视频时长会报告错误。未知时长须等待解码器取得时长后检查；
  未宣称所有容器都能在打开时获得准确时长。

## 当前支持范围

沿用最多四个可达视频节点、共享压缩素材、每实例有界解码帧的现有预算。
本增量没有将视频文件提升到单首配乐的 256 MiB 流式资产预算；既有运行包资产限制仍适用。
摆放结束不超过七天；不支持负速倒播和音高保持变速。
每路视频独立解码，当前精确回跳沿用从源开头恢复的实现，长素材随机定位性能仍待专项改善。

这是多路视频图合成与时间线源区间，视频内嵌音轨尚未自动混音。
下一增量继续多轨音频混合、与导出共用 PCM、内置完整媒体编排示例，然后场景队列/转场。
通用图内事件/动作调度、R6 内容目标和长稳验收均未据此标记完成。

## 验证

Windows 已通过区间数学、图编译/非法属性、FFmpeg 源出点边界、双视频循环/保持/
重叠/跳转、缓存/透明度、工程保存/发布包/Player、中英文真实鼠标拖动和单次撤销。
D3D11 像素验证覆盖区间外透明、同一解码帧的不同淡入值、严格出点保持与源区间循环。
Android Redmi K40S / Adreno 650 原生区间、图、FFmpeg 和发布包检查通过；
GLES 实际像素确认同一视频帧的不同淡入值及设备重建。Windows 15 项受影响回归通过，
日志 `out/r5-media-delivery-tests.log`；手机日志 `out/r5-media-android-tests.log`。
两端已增量构建，Windows Python deploy 完整复制 20 DLL 与资源，Android `adb install -r`
覆盖安装成功，保留数据。内置目录仍为 39 个作品；完整多轨媒体示例随音频混合增量交付。

## 复用

阅读本地 TiXL `VideoClip.cs` 与 `MediaClipSourceRegion.cs`，参考源时间映射、
解码器与合成责任划分。其 C#/全局视频服务、音频图和 bars 时间契约不直接适配本项目，
本次没有导入源码；复用本项目 FFmpeg 播放器、时间曲线、片段交互与纹理合成。
精确出处、固定版本和许可见 [复用记录](../provenance/media_clips.json)。
