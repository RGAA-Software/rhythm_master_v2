# 集群实时数据报 v1

实验协议由 `cluster_protocol` 实现，独立于 graph schema 和运行包 ABI。
不含网络库类型，不分配堆内存；固定上限 100 字节。传输层必须先验证连接身份，
房间层还需执行 epoch、序号、角色权限和接收时窗校验。通过解码不代表允许加入房间。

所有多字节整数为大端，不直接复制 C++ struct 内存。公共头 24 字节：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `RMRT` |
| 4 | 1 | 协议版本，当前 1 |
| 5 | 1 | 类型：1 输入、2 校时请求、3 校时回复 |
| 6 | 2 | 整条数据报字节数，必须与实际长度相等 |
| 8 | 8 | 非零 session epoch |
| 16 | 8 | 非零消息序号，去重由上层执行 |

输入消息恰好 100 字节：偏移 24 为 8 字节目标展示微秒，32/34 为各 2 字节的
group/index，36 起为 32 个 unsigned 16-bit 控制量。编码采用
`floor(value * 65535 + 0.5)`，解码除以 65535；归一化误差不超过 `0.5/65535`。
NaN、无穷和范围外输入拒绝，不静默截断。此布局只代表 participant controls，
不作为尚未定案的 canonical 音频频谱布局。

校时请求恰好 32 字节：偏移 24 为请求端本地发送微秒。
回复恰好 48 字节：回显 epoch/序号/原始发送微秒，偏移 32 为 Host 接收微秒，
40 为 Host 发送微秒，后者不得早于前者。请求端自行记录第四时间戳，
并匹配自己发出的请求后才构造 `ClockProbe`；不能信任远端给出的本地接收时间。

时间允许 `0..2^52` 微秒，不采用 Unix 墙钟。当前版本不接受未知类型、未知版本、
任何截断或尾随字节，未来扩展必须显式版本协商。

Windows/Android 测试覆盖独立 golden 字节、全部 65536 个控制码值、截断/超长、
错误头、时间和身份边界，以及 20000 个确定性变异报文的拒绝或规范重编码。
与 `InputBuffer` 联测验证解码后仍拒绝重放。此变异测试不是完整网络 fuzz 或认证审计。

`ClockExchange` 维护最多 8 个待完成探测，超时 1 秒，所有修改在宿主线程。
回复必须同时匹配 epoch、序号和原始发送时间；错误匹配不能消费合法请求。
本地第四时间戳在 Complete 时填写。倒退本地时间、无法成立的 Host 处理时间、
重复回复、超时回复拒绝。同 epoch Reset 不重用序号；新 epoch 清空旧请求。
与 ClockSynchronizer 联测，并覆盖 10000 次丢回复后的有界回收。

`cluster_send_queue` 单独承担应用发送背压，不依赖传输库：控制帧每条最多 4 KiB，
总计 64 条/64 KiB；资源块最多 64 KiB，总计 8 条/256 KiB。预算包括在途内容。
实时内容最多 1 KiB，保留一条在途和最新一条待发；队列总共最多 16 条在途。
Acquire 优先控制、再实时、再资源；底层完成回调以 generation/id 释放所有权。
Close 清空待发内容但保留在途缓冲，Reset 必须等在途清零且使用新 generation。
Payload 复制为不可变共享字节，同组广播可在加密前复用，不暴露可变 vector owner。

1000 个停滞 Null peer、120 次实时更新的队列测试验证每 peer 最多 2 KiB 逻辑实时
载荷，属于应用队列模型，未创建 1000 个实际网络连接，也不是无线容量/性能报告。
未来传输适配器仍须实现回调退出、接收限额及发送前实时过期检查；只有队列并不关闭这些门槛。

`StreamDecoder` 对一个有序控制/资源流执行重组，前缀为 4 字节大端非零长度。
控制消息最长 4096 字节、64 条/64 KiB ready 队列；资源消息最长 65536 字节、
8 条/256 KiB ready 队列。长度校验先于 body 分配；额外 staging 缓冲最多一条最大消息，
构造不可变载荷时至多再临时复制一条。Feed 返回已消费字节数和背压状态，适配器必须
利用原生接收流控保留未消费后缀，不把后缀复制进无限队列。FIN 前的字节全部消费后
调用 Finish，半个头/半个消息均失败。Cancel 清空待交付内容；调用者串行化其方法。
测试包括全部单次分割点、1000 条合并消息、超长/零长度头、资源字节预算与恢复消费。
