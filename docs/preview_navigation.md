## 既有预览分组合同

沿用每帧最多 8 个预览、256×144、15 Hz 的已验证预算，
增加明确的前后组操作和页码。不会把每个可见节点同时按最终输出尺寸渲染。

主图与当前组件内部图的可见需求交替排列，单次只编译当前组的最多 8 个预览入口。
两边都有需求时首组各获得名额；切换组可遍历全部可见需求，不再只截取前 8 个。
选择节点仍提升其在本作用域内的优先级；需求或作用域变更返回首组，页码不会越界。
编译和资源准备完成后才切换实际画面，沿用迟到结果丢弃和 GPU 资源预算。

分组不会修改工程或作品时钟。最终输出依赖链持续运行；纯预览支路离组后释放状态，
再次进入从当时时间开始建立其局部历史，不承诺重建隐藏粒子/反馈的过去模拟。
本批采用用户主动切换，避免后台自动轮换不停触发编译或重建预览支路。

复用现有 PreviewRouting、CompilerWorker、Viewers 和组件作用域映射，
不增加后台服务或图内设备类型。验证覆盖分页可达性、双作用域分配、选择/作用域变化、
迟到编译防护及真实大图的最终输出连续性。
