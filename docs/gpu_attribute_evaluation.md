# P6.2 有界 GPU 点属性处理验证

2026-09-10，状态：双后端原生探针通过，采用受限实现方向；正式 API／Runtime 尚未交付。

现有 GPU 点固定为每点四个 vec4（64 字节）：位置／年龄、速度／寿命、RGBA、
尺寸／旋转及保留字段。粒子模拟原地写入，纹理取样目前只是渲染视图，尚不能
把处理后的属性作为独立 GPU 输出继续串接。

已阅读本地 TiXL `points/modify/TransformPoints.hlsl` 和
`SamplePointColorAttributes.hlsl`，固定提交为 fbc994d923e8a0142d2ff1b772e4d12248c5b0ba。
采用前者的独立输入／输出、逐点复制再修改、64 线程和范围保护作为探针基础。
原文件保留于 third_party，完整来源、MIT 许可及改动见
`provenance/tixl_point_attributes.json`；与现有通知逐字节核对一致。原仓库只读。

首个实验只处理现有布局中的仿射位置、颜色乘数与点尺寸，保留其他字段；暂不引入
任意用户布局、原生缓冲映射或通用 compute 语言。输入、一级结果、二级结果各自
拥有独立缓冲。测试读取的是测试用可视化纹理，产品 API 不增加 GPU→CPU 同步回读。

必须验证：两级处理逐字段对照、输入不变、65 点的尾部工作组保护、重复写／读顺序，
以及 Windows D3D 与 USB Android GLES 的实际结果和短成本。测试结论不以编译代替。
如果采用，下一步必须补正式句柄／代次、初始化、输入输出别名、容量、预算和取消
合同，再接图节点、需求裁剪、音乐作品和两端交付；不把探针当成用户功能。

## 2026-09-10 原生结果与采用边界

Windows D3D11 和 USB Redmi K40S / Adreno 650 / GLES 3.1 均通过。
共享探针对输入、一级、二级缓冲的 16 个标量逐一编码为 RGBA8 纹理，与 CPU
参考比较（允许 2/255 量化误差）。128 容量仅处理 65 点，剩余 63 点保持哨兵；
65536／262144 容量各抽查头、中、尾共 384 个点，索引高位写入保留属性以检查
抽样偏移。大缓冲没有逐点全量回读，也不把满容量用例标成尾部保护测试。
两组尺寸系数各连续提交 8 帧两级处理，输入保持原值、两级结果匹配。

| 容量 | 三缓冲请求内存 | D3D11 提交＋最终回读 ms | GLES 3.1 提交＋最终回读 ms |
| --- | --- | --- | --- |
| 128，处理 65 | 24576 B | 129.289 / 125.795 | 2.90724 / 1.58406 |
| 65536 | 12 MiB | 117.562 / 134.377 | 16.3615 / 16.6224 |
| 262144 | 48 MiB | 120.115 / 118.809 | 64.8722 / 62.8378 |

数字包含 8 帧提交、测试绘制与同步纹理回读；不是纯 compute GPU 计时、完整作品
帧率或不同设备性能排名。Windows 与 Android 的提交／呈现同步条件不同。
没有进行长时间或热稳定测试。

保留日志：`out/p6-gpu-attributes-regions-build.log`、
`out/p6-gpu-attributes-regions-d3d.log`、
`out/p6-gpu-attributes-regions-android-build.log`、
`out/p6-gpu-attributes-regions-gles.log`。首轮仅头部抽样日志也保留。
`tools/check-boundaries.py` 通过；测试原生资源限于明确列出的 GPU 测试边界。

决定：在现有 64 字节布局和总预算内实现独立输出的点属性映射，不采用任意布局。
产品首版整容量处理，要求源／目标容量相同、源已初始化、句柄有效且不互为别名；
输出初始化只在成功提交后生效。矩阵为有界有限仿射矩阵，颜色和尺寸乘数有界；
沿用设备线程、逐帧顺序、RAII 释放和设备丢失合同。图节点接入后仍须验证
需求裁剪、缓存／取消、节点预览、真实音乐作品与两端交付，才可关闭 P6.2。
