# 集群音乐可视化：PC 主控 + N 台手机

> 2026-09-06，新增产品能力与架构方案；尚未实现，也没有经过容量/同步验收。
> 高性能方向：手机本地渲染，PC 分发统一音频特征、时间、场景和控制。

## 1. 目标与产品边界

一台 PC 创建现场房间，N 台手机在原生 Player 中扫码进入同一个音乐可视化体验。
适用小型聚会、展演、音乐会；支持同画面、分组配色和按角色编排。
这是演出播放/协同体验，不是多人同时编辑节点图，也不是默认屏幕视频推流。

- Host：Windows 优先，macOS 后续；可由 Studio 创建，也可由独立 Player 启动。
- Participant：Windows/macOS Player 可供测试，Android/iOS Player 为最终手机入口。
- 不要求账号、云端登录或产品激活；同一个可达的现场 LAN 是首版前提。
- 默认手机静音，跟随现场扩声。不会让 N 台手机各自播放音乐形成回声。
- 浏览器/免安装、互联网中继、手机作为主控、跨场地演出、专业灯控不是首版承诺。
- N 是可配置成员数，不是无限容量承诺；认证、场景和网络均设置明确上限。
- 保留“先完成并验收 Windows，再实现移动端宿主”的顺序；现在提前定义四平台契约，
  Windows 阶段做协议和模拟客户端，不未经确认提前展开整个移动端工程。

## 2. 核心数据流

```text
PC 音频采集 -> 唯一音频分析器 -> 时间戳化特征/节拍
                                 |
PC 已发布场景包 -> 资源准备 -----> 房间主控/定时场景切换
                                 |
             +-------------------+-------------------+
             v                   v                   v
        手机 Player A       手机 Player B       手机 Player N
        时钟/输入缓冲        时钟/输入缓冲        时钟/输入缓冲
        本地 graph/runtime  本地 graph/runtime  本地 graph/runtime
        本地 GPU 渲染       本地 GPU 渲染       本地 GPU 渲染
```

复用已有规范音频分析和 `.rhythmpack`；不再在手机重复分析同一音乐，
也不新建另一套 filter/spectrum 语义。手机采样自己的麦克风是另一个显式模式。
每帧图像、每个节点预览、GPU 纹理和原生物理指针都不通过网络复制。

手机自行根据屏幕设计分辨率/安全区域渲染。竖屏使用预制布局/明确 fit 策略，
不是把 PC 横屏坐标非等比压缩。分屏拼图需要设备位置、旋转和屏幕边框标定，
与“大家看同一个效果”分开验收，不能由扫码自动推断手机空间位置。

## 3. 网络通道与传输选择

| 通道 | 内容 | 策略 |
| --- | --- | --- |
| 可靠控制 | Join/Welcome、权限、能力、场景 prepare/commit、cue、角色 | 可靠有序、ID 去重、独立限额；不受资源大包应用层排队影响 |
| 实时状态 | 特征频谱、瞬时强度、时间探测、连续控制 | 带 epoch/sequence/time，允许丢失；过期丢弃、不补发旧帧 |
| 资源传输 | manifest、哈希资源、缺失块 | 可靠、可恢复、限并发和限速，演出前预热 |
| 诊断反馈 | readiness、RTT/丢包/晚到、渲染耗时、热状态 | 低频汇总，采样；不让日志成为高频广播 |

优选 QUIC：可靠 streams 处理控制，DATAGRAM 处理时效性输入，资源使用受限 streams
或独立 HTTPS 下载端点。QUIC DATAGRAM 允许非可靠消息，但仍受拥塞控制；
它不是绕过拥塞无限发包的途径。[RFC 9221](https://www.rfc-editor.org/rfc/rfc9221.html)

具体 QUIC 库暂不冻结。先做 C++ 嵌入、许可、Win/macOS/Android/iOS 构建、
证书绑定、DATAGRAM、取消、连接迁移和打包体积 spike；没有证据就不宣布四平台支持。
复用 GammaRay 的异步/重连基础，不把“它有 UDP”误当作已经有可用 QUIC 栈。

MsQuic 与 quiche 是待比较候选，不代表已选定四平台实现；具体风险与来源见
[整体技术栈评估](technology_stack_evaluation.md)。不因为 Windows 表现好就跳过移动端验证。

WSS 为受限网络兼容路径，优先审核现有 Asio2 适配；cpr 仅用于 HTTP 资源下载。
实时和控制分连接，
资源单独下载；发出前只保留最新状态并约束 socket 待发字节。
已经进入 TCP 的旧数据仍可能阻塞新数据，因此该路径必须降低频率/报告延迟，
不能声称具有 DATAGRAM 同等实时性。不可默认退回未认证的裸 UDP。

初版采用加密单播。IP multicast 不是默认方案：需要现场网络与手机权限验证，
不能假设任意 Wi-Fi 都高效转发。未来只有受控现场测量收益明确时才增加组播模式。

## 4. 高并发实现约束

- 事件驱动 I/O、有限执行线程，不为每台手机分配阻塞线程。
- 房间状态修改串行化；asset I/O、hash/decompression 有界并行，不能阻塞音频或主线程。
- 同一组特征只构建/序列化一次，共享不可变 payload；每连接独立加密、拥塞状态和预算，
  不能把一个会话密文直接给所有手机使用。
- 每成员实时通道只保留最新帧/很短的时间窗；可靠队列按条数和字节数限额。
  慢客户端降级或断开，不拖垮整个房间。
- 功能/数量字段要有上限；未知 schema、过大资源、超多节点或恶意 shader 包提前拒绝。
- 数据报以约 1,200 字节网络报文预算作为保守起点；实际应用 payload 还要扣除
  QUIC/加密/IP 相关开销并按探测和协商调整，不依赖 IP 分片发送巨型谱帧。
- 高频特征用固定布局或受限二进制 codec；控制可用单独 Protobuf schema。
  不传整个 graph.pb，也不每帧解析 JSON。
- 初版特征档位建议 64/128/256 bands，30/60 Hz，量化规则和频域映射协议化；
  状态帧附分析配置版本，音频语义不能被省流策略悄悄改变。
- 降级先降低装饰复杂度/实时消息频率，再降低渲染分辨率；保留统一音乐时间与 cue。

仅以每台手机每帧 **512 字节应用数据、60 Hz** 估算：

| 客户端 | PC 应用层发送量 | 说明 |
| --- | --- | --- |
| 10 | 0.307 MB/s，2.46 Mbit/s | 不含协议/无线开销 |
| 100 | 3.072 MB/s，24.58 Mbit/s | 不含重连/资源下载 |
| 1,000 | 30.72 MB/s，245.76 Mbit/s | 不是一个普通 AP 能承载的证明 |

这只是算术预算，不是压测结果。Wi-Fi 空口、ACK、干扰、设备速率、AP 客户端上限
常比 PC CPU 更早成为瓶颈。20 MB 场景发给 100 台设备就是约 2 GB 下发，必须预取。
PC 建议有线接入，场地采用规划过的多个 AP、可达 VLAN、预热/限速和独立演出网络。
普通现场 AP isolation/访客隔离可能完全阻止连接；诊断界面必须能解释。

## 5. 统一时间与现场音乐对齐

1. Host 使用单调时钟建立 session epoch；网络消息使用固定单位的时间值，不依赖
   本地日期、NTP 系统时间是否正确，也不直接比较不同设备 steady-clock 原点。
2. 四时间戳往返探测估计 offset/RTT；过滤高延迟样本，持续估计漂移和不确定度。
   网络上下行不对称仍带来误差，不宣称任意网络毫秒精确。
3. Player 使用可调抖动缓冲和时间映射，以目标展示时间选择/插值输入。
   校时小幅 slew，不能因 offset 更新让整场动画倒退；大的不连续进入受控重同步。
4. 音频帧保留采集 sample time、分析窗口延迟与目标展示时间；全链路诊断不能只量
   socket RTT。起始缓冲可试 50–150 ms，最终按现场数据定档，不写死为所有设备默认。
5. 现场实时音乐不可预知，因此同步多设备与低延迟存在权衡；与 PA 声音的偏差另设
   演出校准。声传播距离也产生差异，不能用网络校时自动消除。不得自动延迟现场扩声。
6. 已知曲目可以预分析、提前发送 timeline；直播输入不能伪称具备同样的提前量。
7. Scene/cue 使用 `execute_at`，提前 reliable delivery、确认和去重；过期 cue 明确
   skip/seek/立即追上策略。瞬时音频 onset 与不可丢的重要演出 cue 是两类数据。

## 6. 确定性、粒子和 Box2D

默认同步“音乐输入、时间、场景版本、随机种子和角色”，不是要求每个像素相同。
不同 GPU、浮点、帧率和物理实现可能产生差异，固定种子不能保证跨平台 Box2D 完全一致。

- 装饰粒子：本地模拟，优先视觉一致与性能；明确是否允许个体差异。
- 严格同步对象：Host 模拟，发送项目定义的 body/transform 值快照，客户端插值展示。
- 大量粒子不默认逐粒子广播；需要严格粒子同步的场景先做数量/带宽预算。
- 不传 Box2D native handles/pointers；physics 包装层不被网络绕开。
- 掉帧固定步进有追赶上限，不能为追赶数秒历史锁死手机。
- 灯光/材质照常本地渲染，跟随复制过来的状态；不是服务器发送灯光纹理。

## 7. 扫码、信任与加入流程

Host 创建房间 -> 显示邀请 QR -> 手机 Player 扫码 -> 安全握手 -> 协商 profile ->
下载/检查缺失资源 -> 校时 -> Ready -> 按指定时间加入演出。

邀请包含协议版本、房间 ID、可达 endpoint、短期高熵邀请、Host 公钥/证书指纹。
扫码得到的信任信息通过原生客户端验证连接绑定；正常公网资源使用 CA 验证。
不依靠浏览器绕过自签名证书，不以 `verify_ssl=false` 代替 pin 校验。

- 多人扫描的房间邀请允许有限期/有限人数复用；每人获得独立短期会话凭据。
- QR 是加入凭据，不是管理员密钥；可撤销/轮换/锁房/踢人，限制握手与下载速率。
- 拒绝错误 pin、过期/撤销邀请、旧 epoch、重放控制和超长消息。
- 多网卡/IPv4/IPv6 endpoint 选择与诊断显式实现；手机与 PC 必须已在可达网络，
  扫码本身不会把手机接入 Wi-Fi，也不能绕过蜂窝 NAT 或 AP 隔离。
- 首版 Player 内扫码；系统相机打开应用的 universal/deep link 是单独的平台接入任务。
- 相机拒绝时允许手工导入邀请链接；不能只凭一个无认证短房间号跳过安全握手。
- 普通参与者不能远程编辑图、执行命令或上传任意资源；互动仅开放白名单参数、
  有限事件和速率受控的聚合输入。
- 日志不记录完整 QR、token、证书私钥、原始音频或完整用户路径。

苹果平台需要本地网络隐私配置；如果以后使用 IP multicast/broadcast，另处理专用
entitlement。扫码直连单播不应不必要地依赖组播授权。
[Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)

Android 的 LAN 权限按系统和 target SDK 分支实现，测试拒绝/撤销和设置恢复；
具体行为随平台版本验证，不把 `INTERNET` 当作永久充分条件。
[Android 本地网络权限](https://developer.android.com/privacy-and-security/local-network-permission)

## 8. 包准备、切换与失联

Host 发布 `PrepareScene(package_hash, profile, generation)`；客户端只下载缺失资源，
验证 hash、解压边界、运行时能力与资源预算，准备完成再报告 Ready。
按共同支持的 profile 或显式角色变体分组，不能静默省略关键节点假装成功。
个人低性能变体要由内容作者标注可接受差异。

Host 在截止时间根据策略选择已 Ready 的成员，发送带 generation 和未来 `start_at`
的 Commit；未 Ready 设备留在等待画面，准备后走新的定时加入流程。
已确认 Commit 的成员仍可能在开始前断线，不能宣称分布式绝对原子切换；Host 显示
未确认/晚到状态，Player 使用明确的继续旧场景/等待策略，不猜测缺失的提交。

新成员获取当前场景、时间、角色及必要快照；不能从音频第零帧开始播放。
反馈/历史累积效果要声明 `analytic_seek / bounded_warmup / snapshot / join_at_boundary`
恢复策略；没有快照能力的 GPU feedback 不假装可瞬间恢复到同一历史状态。

短暂失联保持有限插值，然后淡出或进入安全待机；具体超时可配置并显示。
重连带抖动退避，拒绝旧连接回调/旧帧。Host 重启产生新 epoch，不能混播旧队列。
手机切后台/来电/熄屏/热降频有生命周期策略；首版不承诺锁屏后台仍持续渲染。

## 9. 模块和节点编辑器接口

Transport、RoomCoordinator、ClockSynchronizer、AssetDistributor、InputReplicator、
PeerTelemetry 分离职责，通过组合工作，不制造巨型 SessionManager。
复用范围见 [GammaRay 复用计划](gammaray_common_reuse_plan.md)。

网络服务向运行时发布不可变输入快照，运行时不 include Asio/cpr/QUIC/socket。
独立 render 库不增加网络依赖，Studio 只是房间 UI 的一个宿主。

预制节点/语义输入：

- `SessionTime`：当前会话播放时间、是否同步；离线使用本地时钟。
- `SharedAudioFeatures`：明确的 canonical 频谱/能量/节拍契约，离线接本地分析器。
- `ParticipantRole`：设备所属组、序号、色板、设计布局。
- `CueEvent`：按 ID 和展示时间交付的演出事件。
- `ParticipantValue`：限速/聚合后的互动输入，不暴露成员连接对象。

普通用户从“多人同频”“分组灯海”“竖屏节拍”“碰撞发光粒子”模板开始，
Inspector 只暴露少量颜色、响应、密度、组别参数；不要求手动搭建网络握手节点。
模板作为数据资产，并用测试/工具生成，不写入核心运行代码。
编辑器可模拟角色和时间，不必连接一群手机才能设计。

Host 面板：QR/复制邀请、锁房、人数/上限、Ready、场景/profile、分组、启动/停演、
网络质量、晚到率/丢帧/温度；默认简单面板，高级页再显示网络参数。
所有面板/错误/权限文案支持 zh-CN/en-US，协议 ID 与错误码不随语言改变。

## 10. 存储、安全和诊断

authoring 项目保存角色配置、映射、cue 和演出选项；不保存在线成员、session token、
socket 地址状态或临时钟偏差。运行包保存所需能力/profile 和恢复策略。
协议版本独立于 graph schema，二者都与 runtime feature version 协商。
临时资源放 OS 应用 cache，长期包放应用 data，不写 exe 目录。

本地邀请的身份验证不等于内容绝对安全：包仍执行完整安全校验、预算和 shader 信任策略。
缓存 hash 用强内容哈希，私钥进入平台安全存储；首版不建立互联网公开下载服务。
Host 只绑定所选现场接口；防火墙提示限定网络范围，不自动全局放开公网。

记录聚合指标：加入/准备耗时、吞吐/资源字节、队列高水位、RTT、offset/漂移/
不确定度、输入年龄/晚到/丢失、cue ack、CPU/GPU/present、热降级和原因码。
诊断导出可选择并脱敏，不默认把参与者信息/作品上传云端。

## 11. 分阶段实施与验收

| 阶段 | 工作 | 完成门槛 |
| --- | --- | --- |
| C0 设计 | 本方案、common 复用边界、带宽/安全模型 | 当前文档已建立；具体库/profile 数值待 spike |
| C1 基础 | 最小 async/core 提取，安全下载、QR 生成，传输选型实验 | 独立 target、取消/退出/失败测试、无 Qt、无三方类型泄漏 |
| C2 Windows 集群闭环 | Host + 本地/多 PC Player，join/资源/校时/输入复制 | 一个真实场景同步运行；断线、晚到、切换、撤销邀请通过 |
| C3 Windows 压测 | 10/100/1,000 个协议模拟 peer，网络故障注入 | 有机器规格和负载记录；队列内存有界，渲染/音频不阻塞；不等同手机容量 |
| C4 手机接入 | Windows 主线通过后 Android/iOS 原生 Player 扫码、权限、生命周期 | 各平台真机，不用 Windows 模拟器替代 iOS 验收 |
| C5 现场验收 | 先 10，再 50/100 台；多 AP、预取、角色、长时稳定性 | 发布实测容量档位、质量与设备清单；不足就下调，不默认支持千人 |
| C6 扩展 | 拼屏校准/更大规模/中继/受控组播 | 另立容量与安全门，非首版阻塞项 |

自动化：协议 codec/fuzz、过大字段、丢包/乱序/重复/重放、队列溢出、延迟尖峰、
重连风暴、epoch 切换、时钟漂移、资源损坏/断点、恶意包、错误证书、停止/取消。
用虚拟时间做确定性协议测试，用 Null runtime 做大量虚拟客户端，不为每个虚拟 peer
启一个实际 GPU 渲染器；另外测真实渲染与音频并行负载。

同步验收：受控 LAN 先以 60 Hz 设备间实际显示相位差 P95 <= 33 ms 为试验目标，
另记最大值/分位数/超阈值比例与至少 30 分钟运行窗口；不是已经达到的承诺。
高帧率相机同时拍摄带帧号/时间码的手机画面，核对同一 cue；软件 offset 不能证明
最终屏幕同步。现场音乐延迟单独测量/校准，低频闪烁测试由测试者知情并可停止。
最终阈值按设备/场地结果确认。iOS/macOS 真机缺失时明确等待，不能报全部验收完成。

## 12. 当前结论与下一步

媒体统一 FFmpeg；3D 以 Godot 为主要设计/源码参考，但不随参考模块带入第二套
媒体引擎。相应边界见 [媒体方案](media_pipeline_plan.md) 和
[3D 参考方案](godot_3d_reference_plan.md)。

可以复用 GammaRay 基础能力，但网络架构必须围绕“本地渲染 + 同步输入”设计，
不是把远控视频协议搬来。已授权推进 C1/C2；当前已实现最小后台执行器、时钟估计、
有限输入缓冲及运行时外部输入节点，尚未实现认证传输或完整集群。
架构基础可提前做，手机端仍遵守 Windows 验收后启动的既定顺序。

## 13. 已验证的基础模块（2026-09-07）

`cluster_time` 的四时间戳 offset/RTT 计算参考
[RFC 5905 第 8 节](https://www.rfc-editor.org/rfc/rfc5905.html#section-8)，
只建立项目单调时间映射，不实现 NTP 线协议或修改系统时间。最多保留 32 个样本，
估计漂移限制 ±1,000 ppm，时间修正限制每秒 5 ms；旧 epoch/序号、延迟尖峰和大跳变
触发拒绝或重同步。±100 ppm、1 小时虚拟时间测试在 Windows/Android 通过；
估计不确定度不是屏幕同步精度。

`cluster_inputs` 固定保留 32 帧；连续控制量插值、角色离散切换，超时保持后淡出。
过大间隔不跨空窗插值，未来/过期/重放输入有界拒绝。运行时只读取项目值快照，
提供 session.time、participant.role、participant.control 节点；Studio 可离线模拟。

GammaRay 自有异步基础的提取与测试记录见 `gammaray_common_reuse_plan.md`。
Windows 28 项与 Android 20 项原生测试通过。C1 的安全下载/传输选型和 C2 房间闭环
仍未完成；扫码、现场容量和实际显示相位差需要后续设备验收。

后续增量：QR 生成及识别夹具通过；实时输入/校时数据报采用独立的有界
[v1 编码](cluster_datagram_protocol.md)，Windows 30 项、Android 22 项共享验证通过。
Player 每帧可接收项目输入快照，暂停与换屏保留最后已求值输入；尚未连接房间网络。

`SceneCoordinator` 已实现经过认证后使用的宿主领域状态：最多 1000 个成员（默认
100 是可配置状态容量，不是现场容量结论），严格递增 peer ID/scene generation，
按 package hash/profile 验证 Ready。初次 Commit 只包含 deadline 前 Ready 的成员；
全员策略不满足时保持原状态，部分策略只提交就绪子集，晚到成员必须单独定时加入。
start_at 暂限制为提交时刻后 50 ms..30 s；需结合网络测量调整，不作为显示同步精度。
旧 hash/generation/start_at 的确认、断线成员确认、Stop 后确认均拒绝。

Player 的 `PreparedPackage` 与有界 `PackageLoader` 支持后台验证、哈希及原子安装，
在帧边界移交给 Session；Windows/Android 打开包流程已接入。共享自动验证更新为
Windows 36 / Android 28。传输消息与真实房间 UI、Player 定时切换、入房凭据、
资源分发及屏幕同步仍需继续联通，不能仅凭 Host 状态机宣布 C2/C4 完成。

后续 `cluster_player::PlaybackSchedule` 已把预验证包与 Player 帧边界提交连接：
Ready 必须匹配 SHA-256、实际包 profile 和当前 generation；旧后台完成结果拒绝。
提交最多提前 30 秒，超过 start_at 250 ms 的执行视为错过并保留旧场景，必须重新
提交。初始 commit 和晚加入 commit 均携带原始场景 origin，晚加入不重设共同时间。

只能在新场景边界从空历史开始，不能假装已有 snapshot/warmup。后续媒体/物理加入
时还须正式扩展并序列化恢复策略。以上窗口为暂定协议策略，不是已达显示精度。
