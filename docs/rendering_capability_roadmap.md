## 1. 对标范围与结论

仅比较实时视觉创作所需的渲染能力，不纳入 TouchDesigner 的设备接入、传感器、
灯光硬件、跟踪系统、通信协议等支持。TouchDesigner 是既定产品能力参照，
本地没有其源码；不声称进行了其内部实现审计、最新版功能穷举或同机性能比较。
本轮以我们的实际代码和已有验证为状态依据，不再查网页。

我们已有常见二维音乐视觉和基础三维渲染，但复杂三维、大规模粒子/实例、
通用几何处理、自定义 GPU 计算和高精度合成仍明显不足。不能用模板数量、
图节点数或 GPU 占用率代替这些能力，也没有依据给出“达到竞品百分之几”的数字。

| 渲染方向 | 对标所需能力 | 当前实现 | 主要差距 |
| --- | --- | --- | --- |
| 二维图像合成 | 丰富的生成、滤镜、合成、反馈和数据转换可自由组合 | 已有遮罩、叠加、模糊、噪声、位移、轮廓、映射、反馈/拖尾、图像/视频输入 | 算子广度、可选中间输出、文字/矢量、图像与其他数据域的桥接仍不完整 |
| 精度与颜色 | 浮点中间结果、正确颜色转换、可控高亮和显示映射 | Renderer 已支持 RGBA8/RGBA16F；上传为 RGBA8，Float16 主要用于拖尾历史 | 不能误写为“不支持浮点”；缺贯穿生成/合成/材质/输出的线性颜色与高动态范围工作流 |
| 材质与灯光 | 纹理材质、多类灯光、阴影、环境光照和可扩展材质 | 基础 PBR、金属度/粗糙度、自发光、最多四个方向光 | 缺纹理/法线绑定、点光/聚光、阴影、IBL；当前透明主要是对象排序，交叉透明未解决 |
| 粒子与实例化 | GPU 更新点属性、粒子状态和大批实例变换，避免逐个 CPU 提交 | CPU 粒子/流场/点阵；实例共享 mesh，但逐个设置参数并 submit | 缺通用 GPU 粒子状态、点到网格实例化和实例批处理；共享 mesh 不等于硬件实例化 |
| 程序化几何 | 路径、曲线、网格修改、属性处理、变形、动画 | 基础几何、静态模型导入、层级与独立轴变换 | 曲线/路径、几何修改器、骨架/morph 和动画混合不足 |
| 自定义 GPU 工作 | 用户可扩展图像、材质和 GPU 数据计算 | shader 主要由项目源码内置并在构建时编译 | 缺用户 shader 编辑、诊断、热更新、能力校验和运行包发布闭环 |
| 高级后处理 | 深度等渲染输出可被后续图节点采样，组合景深/遮蔽等效果 | 三维已有深度测试，深度附件以 write-only 创建；不是可采样图输出 | 缺显式深度输出、深度重建/线性化、按需的法线等附加输出和相应效果节点 |

## 2. 交付原则与依赖

每个阶段交付“节点/参数 → 可编辑作品 → 实时预览 → 保存/恢复 → 发布/Player”，
适用时同时验证音画导出。不能只增加 renderer 内部接口或硬编码展示程序。
Android 在每个共享能力增量中跟进，明确具体 GPU/profile；Apple 最后移植。

依赖顺序：**R0 短验证 → R1 GPU 粒子/实例化 → R2 浮点与深度 → R3 材质/灯光 →
R4 几何与 shader 扩展**。R5 创作/播放控制和 R6 内容生产按实际依赖穿插，
不是等全部渲染结束才开始。R0 的最小缓冲契约服务 R1，不建设独立的大型框架。
R2 颜色与深度语义已落地，见 [浮点/深度交付](validation/float_depth_2026-09-08.md)。
R3 的材质/阴影复用同一套语义，避免返工。

| 阶段 | 功能交付 | 具体可见作品/操作 | 完成功能检查 |
| --- | --- | --- | --- |
| R0：短验证已通过 | 在现有 bgfx Windows/Android 适配器验证实例缓冲、计算能力、同步和资源预算；形成支持/不支持的明确结论 | 同一基础 mesh 的批量变换，以及小型 GPU 点状态更新 | Windows 与 USB 手机实际渲染读数；记录真实后端/GLES 能力，不能从 Android 版本推断 compute 可用 |
| R1：规模与动态 | 类型化点属性、批量几何实例、GPU 粒子更新与音频参数输入；节点预览和独立可释放的 GPU 状态 | 可编辑“频谱粒子星云”和批量音柱/光带；不为每根柱子手工堆一串节点 | 同输入对照逐项/批量结果；真实音乐、静音、频段变化、暂停/重置/跳转；短时计数与预算；Studio 和 Player 一致 |
| R2：合成质量 | 显式精度选择、线性颜色/显示转换、高亮保留、tone mapping；可采样深度与线性化节点 | 高频高亮不提前截断的光晕场景，以及可调焦点/景深作品 | 色阶、超过 1 的值、透明边缘、颜色转换次数；透视/正交与横竖屏深度；旧 SDR 作品兼容；SDR 导出映射明确 |
| R3：三维质感 | 材质纹理槽和资产语义、UV/切线/法线、点光/聚光、基础阴影，再接环境光照 | 纹理化音乐雕塑与有投影的节奏舞台，公开光照/材质控件 | 小型已知模型的颜色/法线/金属度与灯光对照；阴影偏移/边界/预算；资源随包携带；手机明确支持档位 |
| R4：创作上限 | 路径/曲线、点属性到几何、常用变形；随后 shader 编辑/诊断/热更新/打包；静态流程稳定后再做骨架/morph/混合 | 音乐驱动的路径光带和变形网格；用户修改 shader 即时看到结果并能发布 | 不合法输入保留旧结果；shader 在选定目标上编译；状态/缓冲绑定受预算约束；旧程序兼容；模型动画与统一时间一致 |
| R5：创作与演出控制 | 曲线切线/批量编辑、参数快照/混合、宏控件；事件/Cue、片段源区间、多轨媒体；Player 公开参数与场景转场 | 同一作品可设计开场/推进/高潮/收束，保存多套参数并按节拍切换 | 撤销与保存/恢复、组件参数映射、暂停/跳转/循环、实时和离线导出一致；不新增竞争播放时钟 |
| R6：内容与产品完成度 | 随每批功能扩展组件/模板、浏览与资源替换/修复、帮助和预览调度；完成基础 50 + 高级 50 品质作品 | 在 UI 里选模板、改少量公开控件/素材，获得不同完整音乐作品 | 按独立构图、动态、音乐响应和可编辑性审核；Android 直接内置选择并覆盖安装；数量与用户品质验收分别记录 |

R1 的规模检查按小型样例、1 千/1 万实例，以及设备允许时更高粒子数量逐档测量。
这些是检查输入，不是保证所有材质/场景/手机都达到某个帧率。
记录 CPU 提交耗时、可取得的 GPU 耗时、实例/粒子数和显存；CPU 时间不能充当 GPU 时间。
仅发现实际问题时扩大短测范围，不把扩大测量变成长期测试任务。

## 3. 关键契约，避免把待定能力提前定案

- **平台能力**：当前 Android 应用走 GLES；compute、可采样深度和格式可用性逐项实测。
  不因 Windows 可用就标记 Android 可用。若手机缺某能力，记录具体缺口，
  采用明确标注的移动实现/档位或报告不支持；不静默更换效果，也不擅自更换整个后端。
- **GPU 数据**：graph/runtime 公共接口使用稳定项目句柄、属性布局和容量描述，
  bgfx/native buffer 留在私有适配器。模拟代次、释放、同步和越界检查由负责模块持有。
  CPU 粒子仍可保留用于明确选择的兼容实现和验证，不被伪装为 GPU 更新。
- **时间**：GPU 状态需定义重置、暂停、循环和 seek 语义；随机种子固定可复现，
  不承诺不同 GPU 浮点模拟逐像素一致。有历史状态的效果不能把时间直接跳过去当作正确预演。
- **精度**：Float16 中间渲染不等于 HDR 显示或 HDR 编码。先完成内部线性合成与正确 SDR
  显示/导出；HDR 文件/显示配置单独列能力，不能在这一阶段自动宣称已支持。
- **深度**：增加显式、按需输出，明确近远裁剪、反转/线性化和投影关系；
  不为每个现有场景强制建立全套 G-buffer，也不要求改成延迟渲染器。
- **材质**：颜色纹理和数据纹理区分，法线贴图需要切线/坐标约定；
  纹理、模型、shader 的资产依赖需一起保存与打包。阴影/IBL分批接入，避免一次铺开所有渲染技术。
- **shader**：先做受约束的图像 shader，之后再扩展材质/compute；明确 uniforms、采样器、
  编译诊断和目标产物。继续使用现有构建/编译工具，不能把 shader 扩展变成任意原生插件 SDK。
- **兼容**：新增节点/格式/能力必须更新运行包验证与明确的版本拒绝或迁移规则；
  现有模板继续能打开。多输出选择需同步到编译器、运行时和 viewer，不靠隐藏附带纹理规避契约。

## 4. 创作任务如何穿插

R1 第一份作品即可暴露粒子数量/发射、频段、颜色和运动强度；沿用已有参数绑定、
表达式和组件，不等待多轨时间线完成。随后补曲线切线与参数快照，使相同作品能有
可设计的动态变化。R2/R3 的作品继续积累可复用合成和材质组件。

事件/Cue、多轨媒体按“片段与统一时间 → 事件与源区间 → 混合/编排 → 导出”拆分，
复用 FFmpeg、已有音频输出及媒体时钟，不另外引入高层播放器。场景队列/转场必须
明确双场景的资源预算与准备状态；在这之前 Android 的直接选择功能保持可用。

内容制作从第一批新节点开始，不以换色、横竖版或设备降级版重复计数。
目前 35 个示例、11 个语义组件和 128 条预设记录均保留；基础/高级各 50、
40 个语义节点、120 个视觉独立预设的品质目标继续跟踪。
见 [内容质量计划](template_quality_delivery_plan.md)。

- GPU 实例/计算接入先检查现有 bgfx 的能力与示例；不另造跨平台图形 API，

  通信继续整体后置，透明原生后缓冲为最后待定功能，不影响图内透明合成开发。

## 6. 每阶段验收与收尾

每个可交付增量只做受影响目标的 20 worker 增量编译、必要回归和短时实机功能检查。
记录改动、节点/参数、可编辑源工程、缩略图、音乐输入、运行包/导出、目标 profile
和已知限制。没有通过的功能继续列缺口；编译成功不能替代实际画面与用户操作。

Windows 每次构建使用已有 Python 自动部署完整依赖到 deploy；Android 每次交付
覆盖安装 `adb install -r`，保留数据，效果在 UI 中直接选择。

**长时间运行、热稳定和数小时资源/音频测试统一留到功能完成后的集中验收。**
现有长稳证据保留，不在每个阶段重跑；当前遇到的卡顿、崩溃和资源错误及时修复。
最终分别标注功能完成、视觉品质审核、各平台验证和长稳验收，不能混成一个“全部完成”。

R3 环境增量（2026-09-08）：IBL 图集预过滤、材质反射/漫反射、节点控制与预览已通过 Windows/Android 检查；63 节点音律珐琅音乐/MP4 回归及两端交付完成。见 [环境光照](environment_lighting.md)。R3 尚余嵌入 GLB 纹理；不把 R4–R6 或视觉/长稳验收标记为完成。
