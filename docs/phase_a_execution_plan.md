## 2. 首阶段纳入与后置事项

用户最新调整：透明窗口/透明后缓冲及其点击穿透验证列为整体路线最后的待定功能，
移出 Phase A/W5 必须验收项，不阻塞当前开发、验收或普通窗口后端采用。
保留已有探针记录；未来确定实施后再验证透明合成，不视为已支持或永久取消。

纳入：四平台共享契约与工具链验证、独立 Null 渲染目标、Windows SDL3 宿主、私有 bgfx 后端、ImGui 绘制桥、
独立 Cyber 基础主题、node-editor 画布适配、最小类型化图和编译/执行、
描述符驱动的基础 Inspector、最小内容注册表、Protobuf 图保存与恢复、中文/英文、
中文输入、DPI、首轮图形能力探针及诊断。

首轮渲染后端的具体版本、Windows 图形 API profile 和字体来源在 W0/W1 记录后试用；
不以机器上已有某个缓存为理由定案。SDL 不承担另一套主 GPU 渲染。
Windows/D3D、Apple/Metal、Android/Vulkan 或 GLES 的能力差异由私有后端和
CapabilityProfile 表达；具体启用组合仍需验证。禁止在核心把 D3D 格式、桌面窗口句柄、
某一 shader 二进制或固定桌面显存预算作为四平台通用能力。

## 3. 最小用户流程与验证内容

首个内容包使用稳定 ID `official.templates.phase_a.signal_texture` 和独立版本。
它是存放在 `content/templates/` 的可加载数据，不能在应用入口按模板名字构造场景。
包包含图、输出 profile、默认参数、双语元数据和确定性测试时间点；不借用无来源媒体。
内容包首版记录所用最小字段及限制，不冒称完整内容包格式已冻结。

最小算子语义：时间源、振荡信号、显式信号采样、颜色/渐变生成、纹理变换、
双纹理合成、单帧纹理反馈及最终输出。仅为该闭环实现需要的窄语义。
Signal 到普通参数值的取样显式表达；Texture 不通过隐式 CPU 回读变成 Signal。
反馈读上一完成帧，帧末写下一状态；初始纹理、重置和尺寸变化策略写进描述符。

验收操作：

1. 启动 Windows Studio，选择该模板，在一个原生窗口中得到可见输出。
2. 打开最终输出与三个中间纹理 viewer；它们使用项目 TextureHandle。
3. 修改颜色、振荡频率或合成量，连线/断线、移动节点，执行撤销与重做。
4. 尝试错误类型连线及无反馈的环，显示关联节点/端口的诊断，已运行的合法计划不被破坏。
5. 切换 zh-CN/en-US，在名称输入框使用中文 IME；节点 ID、参数值和图语义不变。
6. 保存到用户选择的中文路径，关闭并重开；图、参数和布局恢复。
7. 用无窗口测试入口加载同一图，在相同时间步和种子下比较执行结果。

W4 闭环不包含完整 author–publish–play–export；该完整流程仍归 Windows alpha gate。
Null 验证的是图语义、时间和资源调度，GPU 视觉正确性另用参考图/数值采样验证。

## 4. 模块与首批契约

以下名称是职责与字段语义基线。实施模块前落为最小头文件、schema 和契约测试，
不为整张表预建空类，也不通过泛型 JSON 或万能 common 类型联通模块。
公开契约遵循值/引用/span/稳定句柄/明确智能所有权，所有成员声明处初始化。

| 模块 | 首批输入/输出契约 | 所有权、线程与失败约束 |
| --- | --- | --- |
| `platform_api` 与各平台适配（Windows 首实现） | WindowId、WindowMetrics（逻辑尺寸、像素尺寸、scale、safe area）、surface/lifecycle 值事件；文本为 UTF-8，路径为 filesystem path | 主线程管理宿主生命周期；surface 生命周期可短于会话；原生地址只在平台与渲染接入适配内部传递；核心只见 SurfaceHandle |
| `rhythm_render` | Texture/Surface 等带 generation 的句柄、资源描述、RenderPass/绘制命令、FrameStats | 渲染线程独占设备与资源表；一次 Begin/EndFrame；销毁由 RAII 资源所有者统一处理，失效句柄不能命中新资源 |
| `ui_render_bridge` | 将 ImGui draw data 转为项目 UI 顶点、索引、裁剪及纹理命令；UiTextureId 映射 TextureHandle | ImGui/native 类型不进入 render 公共头；借用数据在同步翻译时消费，延迟提交的数据必须拥有内容 |
| `graph_domain` | GraphSnapshot、NodeId、PortId、EdgeId、类型/节点 schema 版本、参数与连接记录 | 领域层无 UI/GPU 依赖；编辑应用层独占可变文档，向外发布值快照；端口方向、类型与 ID 必须验证 |
| 算子与内容注册表 | OperatorDescriptor、ContentId/Version、参数默认值/范围、端口、时间/状态/能力声明 | 按领域注册；展示文案用消息 ID；模板从数据解析，不保留可变的第三方解析树作为运行时对象 |
| `graph_compiler` | GraphSnapshot + 注册表快照 + DemandSet + CapabilityProfile → ExecutionPlan 或 Diagnostics | 后台任务只发布不可变结果，附 document/revision/generation；主线程拒绝过期结果；无效编译保留上个合法计划并显示状态 |
| `graph_runtime` | ExecutionPlan + FrameContext（时间、步长、seed、reset generation）+ 类型化输入 → 值/渲染工作/统计 | 运行状态独占；稳定 StateSlotId 仅在语义兼容时保留；绝不保存 UI 对象、socket 或 AVFrame |
| `editor_application` 与画布适配 | GraphCommand（前提 revision、操作值）→ 新快照/诊断；Undo/Redo；独立布局快照 | 画布只持视图状态；拖动合并为一次历史操作；文本编辑期间快捷键不误触发图删除/撤销 |
| `project_format` 与 `project_service` | ProjectSnapshot → 校验/编码/提交；加载 → 图值与可选编辑状态 | Protobuf/JSON/native 类型私有；事务语义共享、原子文件操作由平台实现；后台保存不可变快照；图提交与索引分开，失败不得污染已提交 revision |
| localization 与 `cyber_ui` | 稳定消息 ID → 当前 locale 文案；控件隐藏 ID 与显示文字分离 | locale catalog 独立资源；Cyber 可依赖 ImGui，不能依赖图业务；完整塑形/无障碍能力单独记录 |

公共 Diagnostic 至少携带稳定 code、severity、可选 NodeId/PortId/字段位置和类型化参数。
错误码由所属模块定义；显示文本由 UI 本地化，不能让核心拼接英文充当身份。
后台取消分为不再接收新任务、取消/丢弃过期结果和等待任务退出；退出时不留回调访问已销毁窗口。

执行不变量：

- DemandSet 包含最终输出和可见/固定 viewer；未被需求触达的分支不执行。
- 编译变化与参数/时间变化分开计数；编辑布局和切换语言不得重编译运行计划。
- 普通环拒绝；显式反馈跨帧切断依赖，禁止同一 pass 读写同一反馈纹理。
- 资源按最后使用帧退役；resize/reset 使旧 generation 失效，UI 纹理映射同步更新。
- viewer 可降频、降分辨率或跳过；最终输出优先，不能随观测节点数量无限分配资源。
- 失败切换不能混合新图的部分结果和旧图状态；诊断明确当前正在显示哪个有效 revision。
- 平台暂停、surface 丢失与重建通过值事件/代际进入运行时；逻辑会话不依赖 HWND 存活。
- 时间用明确单位和本地/会话映射，数据序列化不依赖 sizeof、指针宽度或本机字节序；
  包内路径为可移植相对身份，原生沙箱、文件授权和可写路径由宿主提供。
- shader 坐标、深度范围、纹理原点、色彩空间和格式能力由项目契约/profile 约束，
  不从首个 Windows 后端的偶然行为推导；不支持的能力在加载/发布校验时明确诊断。

## 5. 持久化最小子集

沿用 [持久化方案](project_persistence.md) 的 `CURRENT`、不可变 revisions、
`manifest.json`、`graph.pb`、`editor.json` 和独立资产；不新增临时自定义格式作为正式项目。
W3 前落实首版 GraphProject schema，并为 CompiledProgram 明确独立版本和最小结构；
运行计划持久化/正式发布留给后续阶段，不能用旧 EffectPack 代替它。

首版记录：稳定项目/节点/边/端口身份、type_key/schema_version、类型化参数、
输出配置和本用例的反馈初始/重置规则。布局单独保存。未知节点及未知字段保留，
缺实现的节点有诊断且不执行；未知版本与非法输入按兼容规则处理，不猜测解释。
codec 必须设计未知字段保留路径，不能把 Protobuf 转为领域对象后默默丢失未知字段。

先验证快照 → 写新 revision → flush → 重开校验 → 原子替换 CURRENT。
注入故障覆盖每个写入/flush/校验/替换步骤：替换前重开仍得到旧 revision；
替换成功后得到完整新 revision。无效临时文件和无引用资产不影响两者。
用进程终止测试补充异常注入；这些结果不等于已经证明断电持久性。
editor.json 损坏可重置布局，不能让合法 graph.pb 无法播放。

W3 的边界测试至少覆盖：未知字段/节点往返、重复 ID、错误端口、NaN/Inf、
非法 UTF-8、超限消息/节点数量、路径穿越、图/清单不匹配及哈希损坏。
该闭环可没有外部媒体资产，但不能据此宣称完整资产导入/解压管线通过。
字节数、对象数和嵌套深度限额在开始 codec 实现时写入该模块的具名限制表与测试；
修改限额是版本化决策，不能依赖解析库默认值。

## 6. 实施顺序与进入/退出条件

每一步以受影响 target 增量构建与相关测试通过为完成条件，然后进入下一模块。
默认 20 个 build workers，保留缓存；新改项目代码警告必须解决。
共享模块同时登记 P1 的配置/编译/测试矩阵，能执行的环境当步验证；
不可用的环境留明确缺口，不能把未跑矩阵的模块标为“四平台已验收”。

## 8. 首轮性能试验与证据格式

W0 登记一台 Windows 参考机：CPU、GPU/显存、RAM、OS build、驱动、显示器/刷新率/DPI、

机器资料未记录前不能给出“性能通过”，单台开发机也不能确立最低系统/GPU。

首轮工作负载与目标如下，W0 建立用例数据后登记版本。目标未测，不是产品既定指标。

| 负载 | 试验配置与目标 |
| --- | --- |
| 正确性图 | 第 3 节内容包；固定 seed，时间点 0/0.5/1/10 秒；连续步进反馈与 reset 后重放分别比较 |

修改 profile。变更目标记录原因与前后结果，不覆盖原报告使失败消失。
目标参数及性能基线只有在固定机器、固定负载的复测后才能成为该 profile 的验收依据。
