# 基础阴影（R3）

`scene.shadow` 为输入场景配置一个投影光源。方向光使用正交阴影体，聚光使用该灯
位置、朝向和光锥建立透视投影；点光的全向阴影尚未实现，会明确拒绝。
光源索引先方向光、再局部光，从 0 开始。场景合并调整索引以保留被选中的光源；
两个含阴影设置的场景合并会报错，避免静默丢弃其中一个配置。

## 控件与预算

阴影图为 256/512/1024/2048 四档，默认 1024。滤波提供 Nearest、PCF5（低）和
PCF13（高）三档，旧作品的数值 `0/1` 分别保持 Nearest/PCF5，默认仍为 PCF5。
深度偏移和法线偏移保持独立可调。
方向光可调世界空间中心、宽度和距离；聚光近裁剪面单独配置，远面使用灯光作用范围。
近面必须小于远面；极小近面会损失远处深度精度，不隐式替用户改变这个参数。
场景变换更新阴影中心，范围和偏移保持世界单位；聚光相机始终跟随变换后的灯光。

每次需要更新的阴影增加一次已有场景深度 pass，只让不透明几何投影，保留网格复用、
剔除和批处理。接收场景只对选中灯光乘遮挡，其他灯、自发光保持原行为。
深度/颜色附件均由 Runtime 的独立 ShadowPass RAII 持有，合计每像素 8 字节，
1024 档为 8 MiB，纳入已有纹理总预算。图编译的三角形工作预算包含额外投影 pass。
设置不变且上游没有更新时复用结果；分辨率变化替换两附件，关闭/隐藏预览/重置释放。
新旧阴影图切换时短暂同时计入预算，分配失败不发布半个附件对。

## 坐标与来源

输入保持项目标准右手矩阵和 [-1,+1] clip 深度，接收 shader 映射到 [0,1] 深度
与左上 UV。域外采样返回完全照亮，禁止深度读写同一附件。
PCF5、PCF13 滤波核和几何法线偏移来自固定 Godot 4.5.1 GLES 源码（MIT），见
`provenance/godot_shadows.json`。采用已验证 D24S8 原始深度采样与显式比较，
PCF13 保留中心、远十字、近十字和对角线共 13 个比较，并保留 Godot 在前五个
比较全亮或全暗时的提前返回。没有引入第二个渲染后端、全局阴影图集、级联或点光
立方体阴影。

方向光投影还采用同一固定 Godot 版本的稳定边界算法。Godot 以
`radius * 4 / texture_size` 吸附正交边界；项目合同保存完整投影高度，因此等价为让
投影中心在光空间横向和纵向按两个阴影 texel 移动。小于半格的中心运动保持同一矩阵，
越过边界才整格前进；沿光照深度的运动不量化，聚光透视投影也不量化。

## 短验证与作品

Windows D3D11 和 USB Adreno 650/GLES 3.1 已通过正交/透视聚光遮挡、UV 朝向、
选中灯光、域外照亮、深度偏移以及关闭绑定检查。Null 契约拒绝颜色误绑、
同深度读写、分辨率不匹配、不存在的灯、点光投影和非有限参数。
Runtime 两端通过合并光源身份、缓存、预览、分辨率替换和释放检查。

2026-09-16 的 Windows 增量进一步用同一 256 阴影图和 128×128 接收画面分别回读
Nearest、PCF5、PCF13；红色直射光通道的全图差异依次为 1920 和 1792，证明两次
质量升级都实际改变投影边缘；中间强度像素数依次为 0、24、210，证明高档扩大了平滑
过渡，而不是只改变枚举。D3D11 完整 GPU probe、三项受影响
合同测试和 Windows/Android shader 编译通过，详见
[验证记录](validation/godot_pcf13_shadows_2026-09-16.md)。

音律珐琅更新为 61 指令/79 边，增加聚光阴影与承影舞台。真实 PCM 音乐/静音
平均 RGB 差异 3.270305，低频/静音 10.883352，高频/静音 5.440631，
低频/高频 10.089402。重复 MP4 导出、音轨、时间戳、静音和取消检查通过。
窗口与 APK 已构建并完整部署/覆盖安装，35 个内置示例保持。
