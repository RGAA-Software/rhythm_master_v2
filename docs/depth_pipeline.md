# 显式场景深度与景深

`scene.capture` 一次绘制生成颜色和深度，输出类型为场景图像。`scene.color` 和
`scene.depth` 分别提取颜色纹理与类型化深度，所有权仍属于原采集节点。
旧的 `scene.render` 继续只输出颜色，不强制生成可采样深度。

深度输出携带实际相机的近远裁剪与投影种类。其规范为从近到远递增的窗口深度
0–1；私有 bgfx 适配器负责 D3D11/GLES 的裁剪区间和目标方向。深度不能接到普通
颜色输入，也不能上传 RGBA 像素或作为二维颜色绘制目标。底层 D24S8 仅在适配器内。

`depth.linearize` 可输出相机距离，或将近远距离归一化为 0–1。默认浮点精度和
归一化显示；相机距离模式是数据纹理，不能经过 sRGB 转换。RGBA16F 的有限最大值
为 65504，更远的距离模式输出裁剪到此值。为提高精度，应让相机近远裁剪围住作品，
避免无必要的极大远近比例。

`texture.dof` 接收同尺寸的颜色与类型化深度，提供可连接标量的焦点距离、离焦强度，
以及最大半径 0–32 像素。`dof_shape` 提供 Circle、Box、Hexagon，`dof_quality` 提供
Very Low、Low、Medium、High；四档采用 Godot 4.5.1 固定的圆形步长或分离滤波样本数。
旧文档中的 `dof_samples` 仍可读取，并在没有显式质量档时映射到四档，避免旧作品失效。

近景负 CoC、远景正 CoC 和跨深度遮挡限制来自固定 Godot bokeh 实现。有符号 CoC
存入独立 R16F 权重纹理；Box/Hex 使用两次分离卷积，Circle 与低质量形状使用半分辨率
临时目标，再以原始权重完成最终合成。所有颜色运算保持预乘 RGBA，最终 alpha 取原始
颜色，不强制为 1。深度测试仍沿用当前场景规则：透明物体不写深度，因此这不是多层
透明景深解算。

每个已见尺寸缓存 7 张后端私有临时纹理，共 `17 × width × height` bytes：一张全分辨率
R16F 原始权重、一组全分辨率 RGBA16F+R16F，以及两组半分辨率 RGBA16F+R16F。
持续使用期间缓存保留；某一尺寸组在整个帧内未被任何 dof 命令使用时，帧末回收，
再次需要时按需重建。Circle 每次 3 pass；Box/Hex 的 Very Low/Low 为 4 pass，Medium/High 为 3 pass。
这些 pass 与纹理字节均计入公开帧统计，并与图纹理共同接受 256 MiB 纹理预算。

采集节点和深度提取节点都可在节点内预览；深度预览按自身相机归一化。改变尺寸
或采集精度会替换成对附件，旧句柄失效。纹理复用不会回收仍由采集节点持有的附件。

## 已完成的短验证

- Windows D3D11 与 Redmi K40S / Adreno 650 GLES 3.1：实际采样深度，通过透视、
  正交、横竖尺寸、多个已知平面距离的读回检查；同一颜色目标可切换旧附件和显式附件。
- D3D11：Circle/Box/Hex 的半分辨率与全分辨率质量路径、焦点处棋盘、离焦对比度、
  近远景边界、半透明 alpha、横竖画布及明确 pass/资源预算通过。GLES 3.0 shader 编译
  已通过；Android 实机复验留在最终平台阶段。
- 公共句柄契约：异设备、失效句柄、错误尺寸/类型和非法投影参数被拒绝；预算统计和释放。
- 图与运行时：颜色不能冒充深度；相机信息传递、尺寸变化、精度继承、预览和纹理回收。

代码用例：`src/rhythm_render/tests/depth_gpu.cpp`、`render_contract_tests.cpp`、
`src/graph/tests/scene_graph_tests.cpp`、`src/runtime/tests/depth_runtime_tests.cpp`。
原始 TiXL 文件、MIT 声明、修订和改动范围见 `provenance/depth_pipeline.json`。

“频谱铸场”的 40 节点版本将真实频段映射到 4096 根音柱，响度驱动焦点距离，
再经过浮点柔光与明确的 SDR 映射。作品和应用验收单独记录，不把数值用例通过
等同于所有手机、任意复杂场景或最终视觉品质已验收。
